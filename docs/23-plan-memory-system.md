# 人物记忆与经验传承系统实施方案

> **状态**：规划设计，尚未实现、未排期；本文中的类型、接口和数值均为建议规格。
> **整理日期**：2026-09-09。
> **范围**：结构化记忆、首批 10 种记忆、决策接入、观察、存档与验证。
> **入口**：[文档导航](./README.md) · [长期路线图](./11-plan.md) · [日常生活规划](./20-plan-everyday-life.md)。

## 1. 目标与边界

让人物过去经历的事情改变下一次选择，并让玩家看得见这种因果。例如，同样拥有足够金币的两位户主，一人因多次交易成功倾向采购，另一人因白跑倾向就近采收。两种选择继续改变路线、资源竞争与家庭储备，为不同的家族历史提供条件。

记忆系统不能单独保证长期结局多样。如果资源、制度与收益结构始终相同，学习仍可能让所有人收敛到相同策略。验收要分别观察“记忆是否改变行为”和“差异是否延续到宏观演化”，不能把添加记忆数量当作多样性已经实现。

### 1.1 三类信息分开管理

| 信息 | 职责 | 是否影响决策 |
|---|---|---|
| 结算事实 | 谁在何时、何处获得或失去什么；由真实执行器产生 | 经记忆编码后间接影响 |
| 活跃记忆 | 有限容量、可衰减的个人经验，保存来源与适用对象 | 是，必须持久化 |
| 历史年表 | 对重要事实的长期展示，可筛选和归档 | 否，不从年表反推行为状态 |

人物只记得亲历或有明确传播来源的事情。不能读取全图日志就知道陌生人的遭遇；家户到账可以作为家庭信息，但不能描述成全体成员亲眼看到某次交易。

### 1.2 与现有架构的关系

- L1 持续任务仍按玩家配置的分支顺序首个命中；首期不引入全分支效用排序，不修改有效需求层级。
- 记忆主要影响 L2 的采集/采购与候选地点选择，以及分支内部允许个性化的准备阈值。
- 瞬发、持续任务、连续采收和抢占读取相同的参数视图，保持分支自包含；系统不能扫描人物并直接派发行动。
- `ActiveTask` 继续是持续任务真相源，记忆不能写 `state`、路线、pending 或直接扣账。
- 既有 POI 私有触发器负责可用性；记忆只在可用、可达候选之间表达偏好，不能把断流点重新判为可用。
- 现有禀赋、家资选策与记忆组合时统一限幅，不再叠加一条无条件覆盖分支。应特别审视 `should_buy_resource` 中富裕户主提前返回的路径，避免记忆永远不被消费。

实现依据：[决策现状](./current/06-motivation-ai.md)、[决策局部约束](../crates/sim_core/src/spatial/decisions/AGENTS.md)、[账本现状](./current/12-ledger-system.md)、[快照影响矩阵](./current/13-impact-matrix.md)。文档中部分历史段落存在旧描述，实现前以源码核对实际调用点，不复制旧字段总数或存档版本常量。

## 2. 最小数据模型

建议新增 `spatial/memory/`，按模型、事实编码、更新、效果计算拆分；以下名称用于设计讨论，并非已存在的 API。

### 2.1 输入事实 MemoryFact

| 字段 | 含义 |
|---|---|
| `fact_id` | `(tick, phase_code, producer_id, local_sequence)`，同一运行中稳定且唯一 |
| `recipient_id` | 明确的记忆接收者；一个事实可编码给有限的相关人物 |
| `kind`、`reason` | 类型化事实与原因码，不解析 `current_need` 或中文事件字符串 |
| `subject` | `Self / Poi(id) / Market(id) / House(id) / Group(kind,id)` |
| `resource` | 可选资源种类，防止缺粮经验错误影响金矿选择 |
| `episode_id` | 危机、采购访问、采收站次或修缮任务的稳定标识 |
| `evidence` | 最低生理比例、持续 tick、实际成交量、价格、返程原因等有限数值 |

事实只描述完成的变化。提出求助不等于得到救济，开始返家不等于成功卸货，取消任务不等于市场失信。

### 2.2 活跃记忆 MemoryEntry

合并键为 `(kind, subject, resource)`。建议保存：类型、对象、强度 `0..1000`、首次/最近事件 tick、衰减锚点、强化次数、最近证据摘要、来源 `Direct / Taught`，以及传授来源人物和代数（仅传承阶段启用）。

每人建议最多 **24 条活跃记忆**，其中地点记忆合计最多 **12 条**；同一合并键只有一条。常见经历不会随 tick 无限扩张。历史年表独立限量，不占用活跃槽位，也不恢复被遗忘的经验。

还需保存识别过程状态：危机锁存/起始 tick/最低值、站次累计采收、市场访问累计成交和原因、旅行时长与中断原因、当前 episode 序号。它们也是行为状态，不能只存最终 MemoryEntry，否则存读档会重复强化或丢失半次经历。

### 2.3 只读效果 MemoryEffects

在个人决策相位开始时，以当时记忆计算一份临时视图；不作为第二份可独立修改的状态。输出限于：

- 水、粮、木的个人备货阈值偏移；
- 指定 POI/资源的候选成本修正；
- 指定市场/资源的采购倾向；
- 非紧急工作的出发体力与远途成本修正；
- 自家住宅提前修缮阈值。

每项效果附主要来源记忆键、基准值、修正值与钳制原因，供行为诊断。零强度、无适用对象时回到当前基准行为。

## 3. 事实进入记忆的时序

保持现有 tick 子阶段顺序：再生 → 代谢 → 交互 → 房屋 → 路网衰减 → 运动 → 决策 → 账本 → 清理。

1. 各执行器在确认数值变化或任务结果后生成紧凑事实，不能在候选评估时写记忆。
2. 所有事实先进入本 tick 暂存区；同阶段按稳定实体 ID 和局部序号归并，不依赖 HashMap 遍历顺序。
3. 清理阶段移除实体前，将事实按 `fact_id` 提交到仍存活接收者的记忆。已死亡者只留下符合历史年表策略的事实，不保留可行动的记忆副本。
4. 本 tick 新记忆从下一次个人决策相位起生效。同 tick 的早晚决策者都不能提前读到本 tick 新记忆，避免阶段先后造成隐性优势。
5. 危机与访问探测器在对应物理阶段更新；事件缓冲区在完整 tick 边界清空。存档首期仅允许完整 tick 边界，子阶段 profiling 不开放存档。

暂存容量按事件数量增长并设置监控；不得因固定缓冲区溢出静默丢弃影响行为的事实。对持续状况先按 episode 聚合，避免每 tick 生成一条事件。未来多线程需要先确定归并顺序，再改变生产方式。

只读快照、Inspector、暂停和关闭浏览器面板都不得强化或衰减权威状态；渲染频率不会改变记忆。

## 4. 形成、强化、遗忘与冲突

### 4.1 时间与强度

所有时间最终使用整数 tick。设计参数可用“个人决策周期 D”表达：`D = agent_decision_interval_ticks`；初版配置注入时换算为 tick，并在运行中以 tick 为权威。不能使用墙钟时间、帧数，或直接把现有配置中的“模拟秒”当作现实秒。季节周期、成年年龄与 D 的压缩比例应分别测量，不把某个记忆时长宣称为真实几年。

建议整数线性衰减，便于分批推进与读档一致：

`effective(t) = max(0, anchor_strength - floor((t - anchor_tick) * 1000 / lifetime_ticks))`

`lifetime_ticks` 表示满强度从 1000 衰减到 0 的时间；弱记忆会更早消退。读取时从同一锚点推导，不能每次查询都向下取整并重设锚点。强化前先算当前强度，再加事件增量并限幅到 1000，同时重设锚点。乘法用足够宽的整数，拒绝零寿命和非法配置。

推荐基础增量 250，重大危机最多 500；重复事件须完成一个 episode 并经过最短间隔才能强化。同一事件不因多次快照、多个退出路径或连续成交小步反复计数。

### 4.2 持续危机与常规成功

- 危机在越过进入阈值且持续达到门槛时记一次，直到越过独立恢复阈值才重新武装。严重程度由确认前的最低比例与持续时长计算，首次确认之后不逐 tick 增加。
- 普通成功按一次完整站次/访问聚合，且设独立成功强化冷却；不能让每天喝水的数千次扣减压过一次严重经历。
- 恢复本身用于解除锁存；没有对应的成功事实时，不直接伪造一条正面记忆。

### 4.3 正反经验并存

同一 POI 可同时有“采收顺利”和“到访断流”；同一市场可同时有成功与白跑。按衰减后强度计算净偏移，最后钳制，UI 仍展示两条证据。最近一次失败不会立即抹除长期成功，也不累积为永久封禁。

容量满时先删除有效强度为零的条目，再淘汰“当前有效强度最低 → 最近强化最早 → 类型码 → 对象类型/ID → 资源码”最先者。所有比较使用固定顺序；淘汰不触发新记忆。死亡或拆除后的对象不能被解引用；已失效对象的记忆可继续衰减展示，但不转移给新房、新市场或继任国王。

## 5. 首批 10 种记忆

以下强度上限均为 1000；效果数值是首轮校准起点，不是已验证平衡。D 和衰减规则见 §4。每种记忆都必须能从结构化事实解释，不额外引入疾病、战争、承诺或不存在的物理伤害。

| 编号 / 类型 | 形成条件与亲历范围 | 行为效果（满强度建议上限） | 满强度寿命 / 重新强化间隔 |
|---|---|---|---|
| M01 挨饿经历 `FoodScarcity` | 本人饱食度/容量低于 20%，连续 2D；恢复到 50% 才结束危机 | 粮食个人备货开启、停止阈值同时提高，最多基准的 20% | 240D / 每个新危机且至少 8D |
| M02 缺水经历 `WaterScarcity` | 本人水分/容量低于 20%，连续 2D；恢复到 50% 后重新武装 | 水储备两阈值最多提高 20% | 240D / 新危机且至少 8D |
| M03 寒期缺柴 `HeatingShortfall` | 气温低于现有烧柴门槛，非零级自家住宅实际烧柴需求未足额支付，连续 2D；只通知期间实际在宅的非胎儿成员 | 木储备两阈值最多提高 25% | 480D / 连续足额供暖 2D 或暖期 2D 后重置，至少间隔 8D |
| M04 资源点扑空 `PoiDisappointment` | 本人到访后，因该点资源不足退出/转站，本站有效采收量低于计划量 10%；途中仅看到锁存关闭不算亲历扑空 | 对同 POI、同资源的候选成本最多加 25% | 80D / 每站次一次且至少 4D |
| M05 熟悉的丰产地 `PoiReliability` | 本人在该站采得出发/进站计划量至少 80%，且未因生理危机中断；本人自饮自食则按计划恢复量计 | 同 POI、同资源候选成本最多减 10% | 160D / 每站次一次且至少 8D |
| M06 顺利采购 `MarketReliability` | 访问结束时，某资源实际成交量达到访问计划量 80%，支付与物资流转均结算成功 | 同市场、同资源的可选采购成本最多减 10% | 160D / 每访问每资源一次且至少 8D |
| M07 榷场白跑 `MarketDisappointment` | 到场后因无库存/当前报价超出当时可用预算，结束访问时该计划资源成交量低于 10%；记录具体原因 | 同市场、同资源的可选采购成本最多加 25% | 80D / 每访问每资源一次且至少 4D |
| M08 远途劳顿 `JourneyExhaustion` | 从出发到途中因体力触发真实任务抢占/取消，且旅行累计超过 4D；正常满载返程不算失败 | 非紧急工作出发体力门槛最多加容量的 5 个百分点，远途候选成本最多加 15% | 120D / 每任务一次且至少 8D |
| M09 险些失修 `HouseNeglect` | 本人拥有/居住的住宅耐久降至现有修缮触发阈值的一半以下时，首次观察确认；恢复至现有修缮触发阈值以上才重置 | 对该房屋的修缮触发阈值最多提高 10 个百分点，合计不超过 95% | 320D / 新失修 episode 且至少 16D |
| M10 获得救济 `ReliefReceived` | 家户确实收到宗族或地区水粮救济；首期只写入到账时户主，来源按实际付款团体 ID 记录 | 来源仍有效、本人仍属该团体时，最多抵消水粮“记忆额外储备”的 5 个百分点；不低于基准储备 | 120D / 每次结算聚合且至少 8D |

### 5.1 关键归因约束

- M01/M02 新生儿也可能经历低生理数值，但首期仅对能自主决策的非胎儿人物启用编码；儿童体验与成年后的影响留到传承阶段统一设计，避免初始化即贴危机标签。
- M03 名称表示“供暖燃料不足”，不能写成“冻伤”或“家人冻死”。现有健康指标和供暖规则不能证明这些额外因果。
- M04/M05 使用进站时冻结的正数计划量；小于最低有效量（建议背包容量或生理容量的 10%）不编码成功/失败，避免微小补采刷记忆。分母不随库存或记忆变动追涨。
- M06/M07 同样冻结每资源采购计划量，并记录实际成交；一趟可“买到水但没买到粮”，不能把不同资源归成全市场好坏。行囊已满、需求由配偶满足、主动取消、返家自救不记市场失败。
- M08 是长途过程与体力中断的共同事实，不宣称已证明某段道路导致劳顿；首期记本人远途经验，不给全路网永久加惩罚。
- M09 不等同于房屋已经倒塌；迁居后旧房记忆不影响新房，不因住户变化传染给陌生人。
- M10 表示实际收到支持，不等于效忠国王，也不创造拒税、赠礼、迁籍等当前未接入的行为。它只消减额外保险量，使自助与互助经历产生有限差异；若实验显示导致救济依赖，应下调或停用效果，保留事实展示。

### 5.2 玩家可能看到的差异

经历缺粮者更早准备粮食；被同一果丛多次扑空者在有替代点时改换目的地；采购成功者更愿意用金换时间；远途疲惫者先恢复更多体力再出门；获得公共支持者仍保留基本储备，但不再把所有余裕都投入额外囤积。

这些都是条件性倾向。饥渴自救、支付能力、房籍、成年/婚姻、材料成本、生育门槛和行囊容量等硬条件继续优先。

## 6. 决策消费契约

### 6.1 个人备货与家庭账本

家庭库存仍只有家户账本一份真相源；记忆不创建个人虚拟库存。已有 `family_stock_active` 为个人锁存，允许同一家人有不同的准备倾向，但都读同一实际余额。

建议统一提供只读 `effective_stock_band(agent, resource)`：将 M01/M02/M03 的加成与 M10 的抵消合并，再同时缩放基准开启/停止阈值，保证 `0 <= on < off`。总加成限制在水粮 20%、木 25%，M10 最多抵消 5 个百分点，禁止降低基准。

必须接通锁存更新、分支守卫、现场完成判断、连续采收队列与市场需要量判断，不能只改一处。执行中的站次/采购计划量冻结，避免阈值漂移导致“永远采不满”；下一任务再读新阈值。阈值下降时按现有相位重新评估锁存，不由记忆模块强制切状态。

### 6.2 选点与选策

候选先经过当前资格、可用性、可达性与支付能力检查。建议在可选方案的既有成本上乘以记忆修正系数；正反效果相抵后，地点/策略总系数钳制为 `[0.75, 1.35]`。基础成本必须非负且单位一致；跨采购与采收比较需明确旅行时间、采收时间与金币成本换算，不能把距离与金币直接相加。

若第一阶段不引入跨策略统一成本，可先仅对野外 POI 候选加权；采购记忆接入前再将现有布尔选策改造成具有明确可行性与偏好分离的选择器。市场信任不能只加一个无人读取的数值。

只有一个可行方案时忽略负面偏好；紧急自救与野外断流的市场兜底不受恐惧否决。偏好不能改变 A* 边权和共享路径缓存；先在候选目的地评分层使用已有距离/路线估计，实际路线仍由当前寻路器生成。

### 6.3 劳顿与修缮

M08 只增加非紧急工作的准备余量，不能要求体力超过容量或阻止紧急取水取食；不会在 tick 中直接命令返家。M09 只改变自家修缮分支的触发阈值，与当前禀赋修正合并后限幅；材料、资格与修缮完成规则保持权威。

### 6.4 防止新一轮锁定

不设永久黑名单；遗忘持续进行，单一可行来源始终允许尝试。对有替代方案的安全备货，可在后续阶段增加确定性复查：例如每 32 次同类安全决策，按稳定 ID 轮换一次基础成本相近（差距不超过 10%）的候选，重新取得经验。复查计数必须存档，不能通过快照读取推进。

复查属于第二阶段实验项，默认关闭；先用自然遗忘验证是否已经能恢复尝试。目标是允许重新学习，不是定期强制人物冒险。

## 7. 家庭影响与代际传承（后续阶段）

首期个人记忆不随成婚、分家、继承资产自动复制。家庭会通过共同账本间接受到个人选择影响，但不是全家立即获得相同经验。

后续采用“长期同住学习”，不使用出生时复制父母全部记忆：

1. 在儿童期按已有家户关系记录共同生活的成年监护人暴露时间，仅跟踪有限候选，不全图两两更新。
2. 成年时选共同生活时间最长的至多两位监护人；并列按 ID。监护人必须在实际共同生活阶段拥有相应有效经验，不能从成年当天的记忆倒推整个童年。
3. 初版仅允许水、粮、木准备倾向传承，各取加权平均后乘 0.25，总强度不超过 250，并明确标记“家庭教导”。不传承具体 POI/市场评价、政治忠诚或私人恩怨。
4. 传授型经验寿命为同类亲历记忆的一半；允许与亲历合成但不重复叠满。没有亲历强化的纯传授记忆不再次传授，避免无限代复制。
5. 成婚保留双方个人经验；新家户不生成额外集团记忆。实际帮助、共同劳动、授艺与关系记忆需等对应日常行为落地后新增事实类型。

该方案需要童年暴露摘要及成年一次性结算标志进入存档。尚未实现儿童观察时，界面不能把先天属性或父母经历描述为孩子的亲历记忆。

## 8. 模块落点与实现顺序

| 阶段 | 建议内容 | 完成标准 |
|---|---|---|
| P0 只记事实 | `memory/` 模型、M01/M04/M06/M07 编码、去重衰减、存档、只读观察；效果开关关闭 | 同一段经历只记一次，存读档与分批推进一致，来源可追溯 |
| P1 最小行为切片 | M04 的 POI 偏好、M06/M07 采购偏好，再接 M01 个人备粮阈值 | 能在相同当前条件、不同历史下解释不同选择；没有自救阻断 |
| P2 首批十种完整接入 | 其余六种、合并限幅、失效对象、满容量、必要时复查 | 每种均有触发、退出、消费者和观察证据；长程成本可接受 |
| P3 家庭传承 | 共同生活摘要、成年传授、来源与衰减 | 子代存在有限历史影响，不能永久复制家族标签 |

建议职责分配：

- `agent.rs`：挂载有限记忆与 episode 探测状态，不堆放编码规则。
- `memory/model.rs`、`encode.rs`、`update.rs`、`effects.rs`：类型、事实映射、生命周期、只读修正；按实际规模拆分，遵守单文件行数规范。
- 代谢、POI 交互、市场结算、房屋维护、账本救济：只生产自己能证明的事实。`transition.rs` 提供任务完成/取消原因与 episode 收口，不从兼容状态猜原因。
- `world_tick.rs`：完整 tick 末提交记忆；同时核对 profiling 的 `tick_subphase` 路径，保证两种推进方式经过同一提交点。
- `decisions/`：注入 MemoryEffects，维护统一阈值与候选评价入口；全局决策顺序权威仍在前端配置。
- `world_save.rs` 与实际存档结构：持久化全部行为所需状态；不能只序列化 UI 摘要。

## 9. 存档、快照、配置与性能

### 9.1 确定性和持久化

首期记忆形成、衰减、合并、淘汰不消耗 RNG。若以后增加学习概率，只能沿项目确定性契约处理，并持久化相应状态。

存档包含记忆、探测器、episode 序号、锚点、复查计数（启用时）、传承摘要（P3）；加载不重新编码事件、不重新掷点、不从日志重建记忆。新增结构时审查当前 `SAVE_FORMAT_VERSION` 后按不兼容情况升级，不能照抄文档中的历史版本号。对象引用按世界隔离，重置世界清空所有记忆与调试缓存。

记忆开关建议明确分为“事实记录”与“行为效果”；用于实验的运行配置随存档与回放输入保存。效果关闭时既有行为路径和 RNG 消费保持基准；记录关闭且无记忆状态时避免额外分配。

### 9.2 快照与界面

遵守 `snapshot.rs → world_snapshot.rs → snapshot_bin/encode.rs → snapshot-bin.js + rustworld.js` 同步链；生产读取仍走 FABS，JSON 调试接口只用于既有漂移比对门禁。

常规快照仅提供记忆数量与当前主要影响。选中人物时通过后续新增的只读详情请求获取最多 24 条摘要，不能默认每帧为全体人物生成长文本。详情协议应返回世界身份与快照 tick，前端切换世界或人物后丢弃过期响应；未来新增接口须更新 WASM 局部文档。

Inspector 建议显示“经历 → 当前影响 → 本次选择”，例如：

> 曾在东泉扑空（80 tick 前，强度 420）；东泉候选成本 +10.5%。本次选择南泉，两处均可用。

如果没有影响当前选择，应写“当前未影响行动”，不能把最强记忆自动当作决策原因。已生效偏好、被限幅、因紧急自救忽略均可解释。历史文字由结构化模板生成，不依赖 LLM。

### 9.3 配置与预算

容量、进入/恢复门槛、持续时间、强化冷却、寿命、最大效果、最低有效采收量与功能开关统一走 SimConfig。新增字段遵循命名 const、结构字段、Default 三处同步；若拆分前端配置文件，必须同步启动注入、`config-check.js` 与 WASM 工具配置合并。

首轮性能目标：每人记忆及探测器平均不超过 2 KiB（以实际布局测量，不包含历史文本），同人口同负载下新增 tick 耗时目标不超过 5%。记忆处理复杂度应接近 `O(事实数 + 本拍决策人数 × 24)`；不逐 tick 扫描全体记忆做遗忘，不做人物两两关系矩阵。预算是进入后续阶段的条件，测不到则先保留事实记录、降低功能规模。

## 10. 验证与防趋同实验

### 10.1 必须满足的工程不变量

| 场景 | 观察结果 |
|---|---|
| 危机持续数千 tick，随后恢复再复发 | 每个 episode 一次强化，恢复后新 episode 可形成 |
| 采收/采购成功分成很多小步 | 与同总量的相同访问结果一致，不按小步刷强度 |
| 站次进行到一半保存再读取 | 累计量、退出原因、记忆强度与直接继续一致 |
| 连续运行与任意分批推进；频繁/不读快照 | 记忆和世界结果逐字节一致 |
| 地点失效、换世界、人物死亡、成婚分家 | 无悬空解引用、串世界、复制经验或额外强化 |
| 正反记忆冲突、容量满、同强度淘汰 | 限幅和淘汰顺序稳定，无无限增长 |
| 唯一可用水源有负面记忆 | 仍可自救，不因偏好失去可行方案 |
| 玩家重排分支，瞬发与连续采收同时参与 | 分支守卫自包含，无旁路指挥与不一致阈值 |
| 效果关闭、观察开启 | 不改变原有行动与 RNG 消费；对比时排除新增观察字段 |

实现时运行对应 Rust/WASM、确定性、快照、配置与前端门禁。临时验证脚本按项目规定运行后删除，不提交持久化单元测试或固定故事断言。

### 10.2 长期实验设计

建议先用 12 个固定种子筛查明显问题，再用至少 30 个种子比较四组：无记忆、只记录、个人记忆生效、个人记忆加传承。输入地图、配置和干预序列成对相同；测试区间同时覆盖多个季节与至少三个成年周期，按实际模拟时间尺度换算 tick，不以现实运行分钟判定“长期”。

先验证微观因果：从相同世界状态分叉，一支保留经历、一支只清除目标记忆，比较下一次具备替代方案的选择。诊断干预仅用于实验，不能作为生产记忆来源；RNG 状态与其余输入保持相同。

长期记录人口与灭绝比例、营地人口份额、家族存续与更替、财富集中度、采购占比、POI 访问分布、生存失败与记忆强度分布；按相同 tick 和相近代际各比较一次，并对灭绝世界单列，不能把大量灭绝误报为多样性。

关注三个判据：不同历史是否改变后续选择；这种改变是否带来超过单次行程的家庭/空间差异；差异是否只是统一增加劳动、延迟发育或放大死亡。若人物全部饱和为同一种记忆、所有家庭都提高到相同储备，先减少强化/增加遗忘并核对共同压力，不继续增加记忆类型掩盖问题。

正式实现后的实验数据再决定数值与验收阈值。本文不承诺一定减少宏观趋同；若微观差异有效而宏观仍收敛，应继续检验生态历史、地方比较优势和制度反馈。
