## 1. 目标与非目标

### 1.1 产品目标

1. 用户的决策顺序、存档文件和模拟状态形成清晰的启动契约：没有明确的本地存档文件就不运行模拟。
2. 拍卖大盘能区分在售、成交、流拍三种状态，并在高倍速下仍能稳定切换房源。
3. 家户财富统计可直接定位最富家户；榷场在采集链路断流时成为真正的即时生存兜底。
4. 王国税收不仅停留在公仓余额，还能以可审计的内帑流水反馈给现任国王。

### 1.2 非目标

- 本版本不改变房屋竞价资格、报价公式或麦穗阶段规则。
- 本版本不把榷场加入免费野外水源/粮源池，不改变普通采集的施密特触发器。
- 本版本不引入国王私人资源的消费 AI；内帑只作为随身黄金余额存在，后续仍可按现有规则回家入账。

## 2. 统一决策表

| 事项 | 决定 | 原因 |
|---|---|---|
| 马斯洛顺序持久化 | `localStorage` 是用户侧唯一运行时真相源；服务端写盘降为兼容迁移，不再作为正常保存路径 | 用户无需本地服务器也能保留编排结果，静态部署行为一致 |
| 启动存档 | 首次进入显示“建立存档文件”门禁；未成功取得 `.json` 文件句柄前不创建/不 tick 世界；取消即停留在门禁 | 满足“必须先申请建立存档文件”，避免用户误以为状态已保存 |
| Firefox | 明确判定为不兼容并阻止开始游戏，不提供 localStorage 降级启动 | 用户已明确不兼容 Firefox；避免出现无法兑现文件存档承诺的半兼容状态 |
| 流拍率 | 累计口径：`flopped / finished`，只统计已结束场次；正在拍卖不进分母 | 与成交历史可核对，跨时间和倍速稳定 |
| 最富家户 | 按账本 Gold 降序，金额相同取较小 household id；同时展示 id 与金币 | 确定性、可定位、与其他并列排序规则一致 |
| 市场兜底 | 只对水/粮采集链路生效；支付从家户账本远程结算，户主无需先回家，也不要求身上已有金币 | 采集现场发现断流后可以立即改道，避免无意义往返 |
| 国王内帑 | 每 100 游戏秒（3000 tick）结算一次；从当前地区公仓 Gold 转至当前国王 `Personal(king_id)`，金额为结算时公仓余额的 10% | 时间基准明确，账本来源/去向可审计，金额不会因中途余额变化产生歧义 |

## 3. 功能设计

### 3.1 马斯洛优先级保存到浏览器

#### 用户体验

- 决策引擎拖动排序或分界线后立即写入浏览器 `localStorage`。
- 页面重新打开时，先加载内置默认值，再应用浏览器覆盖值；覆盖值非法、版本不匹配或长度不符时丢弃并回退默认值。
- 提供“恢复默认顺序”按钮：删除覆盖值、热注入默认配置，并显示一次性提示。
- 不把用户配置静默写回仓库文件；服务端接口仅保留旧版本迁移读取/清理能力，避免多端覆盖。

#### 数据约定

```text
flowaccord.decision-order.v1 = {
  schema: 1,
  order: string[],
  divGaps: number[],
  levels: number[],
  savedAt: number
}
```

校验条件：`order` 必须是已知分支 ID 的排列；`divGaps` 数量为 4、严格递增、每层至少 1 个 action；`levels` 长度与 `order` 相同且只能为 0~5。任何失败都不影响模拟启动，只回退默认顺序。

### 3.2 存档文件启动门禁（仅支持 Chromium）

#### 用户流程

1. 页面打开后显示阻塞式启动层，不展示可操作的模拟画布。
2. 用户点击“建立存档文件”，调用 `showSaveFilePicker` 创建/连接 `.json` 文件。
3. 成功取得句柄后写入一个最小合法存档（含 schema、版本、seed、tick=0），再初始化 WASM 世界并解除门禁。
4. 用户取消、权限拒绝、写入失败或文件格式校验失败时，保持暂停在启动层，说明原因并提供“重新选择文件”。
5. 检测到非 Chromium 或缺少 File System Access API 时，显示“不兼容当前浏览器，请使用 Chrome/Edge”，不创建世界、不启用 localStorage 代替文件。

#### 句柄与生命周期

- 文件句柄只保存在当前页面会话；刷新后重新申请，这是浏览器安全模型要求。
- 游戏运行后自动保存继续写入该文件；手动保存、退出前保存和现有读档入口共用同一个句柄。
- 如果用户在运行中断开/撤销权限，立即暂停模拟并回到“重新连接存档文件”门禁，不能静默改写到其他存储。

### 3.3 拍卖流拍率统计

#### 定义

一次拍卖场次从 `auction_state` 创建开始，到成交或明确结束（耐久度出清、房屋被其他流程占用、拍卖取消）结束。

```text
finished = sold + flopped
flopRate = finished > 0 ? flopped / finished : 0
```

“正在拍卖”不属于 finished；观察期只有报价但最终无成交，仍算流拍。重复挂牌形成新场次，不能沿用上一场次结果。

#### 数据与展示

世界级累计计数（随存档保存）：

- `auction_started`
- `auction_finished`
- `auction_sold`
- `auction_flopped`

房屋级历史成交/流拍明细仍保留最近 N 条；统计大盘展示：流拍次数、已结束场次、流拍率、当前进行中场次。所有计数满足 `finished == sold + flopped`，异常时以前端只读校验提示而不是自行修正。

兼容旧存档时，若只有历史成交记录，`sold` 可由成交档案重建；无法判断的旧场次不补入分母，并显示“历史数据不完整”标识。

### 3.4 “正在拍卖”高倍速房源切换

#### 问题判断

当前风险不是倍速逻辑本身，而是高频刷新时用 `innerHTML` 重建房源卡片：用户按下鼠标后，卡片节点可能在松开前被替换，导致事件落不到原节点。倍速越高，替换窗口越密集，故表现为“倍速相关”。

#### 方案

- 房源条改为 keyed DOM：以 `houseId` 维护卡片节点，刷新时只更新耐久、报价、阶段等文本节点，不重建未变化卡片。
- 点击采用容器级事件委托；`pointerdown` 记录 house id，`click` 使用当前仍存在的 id 完成切换，禁止依赖旧节点引用。
- 选中房屋在刷新期间保持；若房屋成交/流拍从 active 集合移除，才切换到下一个有效房屋或空态。
- 历史页继续完全隐藏 active 房源条，避免两个页面共享“当前房源”状态。
- 加入高倍速回归场景：512× 连续刷新时，对每个房源执行按下→多帧刷新→松开，切换成功率必须 100%。

### 3.5 最富家户 ID

全局均值大盘和家户制度大盘均显示：

```text
最富家户：#<household_id> · 🪙 <gold> 金
```

统计只看存续家户的 `balances.Gold`。无家户时显示“—”；并列按 household id 升序取第一户。前端不依据数组顺序或户主 Agent ID 猜测最富家户。

### 3.6 采集现场断流后的榷场直达

#### 触发条件

仅在 `SeekingWater`/`DrinkingAtWater` 或 `SeekingFood`/`ForagingFood` 链路中触发：

1. 当前 Agent 对该资源类型的所有野外 POI 私有施密特触发器均关闭；
2. 对应家户资源低于市场应急阈值；
3. 存在可达 Market 节点；
4. 家户账本 Gold 足以支付至少一笔最低采购金额；
5. Agent 仍满足市场派遣体力门槛。

水荒只检查水源，粮荒只检查浆果丛；不得因为木/石/金断流进入市场。

#### 状态转换

```text
现场采集 → 发现同类 POI 全关闭
       → 复核家户账本与市场价格
       → 原地平滑掉头
       → SeekingMarket → BuyingAtMarket
```

不得先切换 `ReturningToCamp`，不得瞬移回家。市场购买直接从家户账本远程扣除 Gold；购入水/粮进入现有市场交易与行囊流程，回家后再按正常卸货规则入账。若市场库存/余额在重规划前已不满足条件，则保持现有返家逻辑。

### 3.7 国王内帑

#### 结算时序

- 一个游戏年仍由四季系统定义，但内帑不按年结算，而按固定 **100 游戏秒 = 3000 tick** 结算。
- 世界维护 `last_royal_payout_tick`（或等价的下一个结算 tick），存档/读档必须保留，防止刷新或高倍速重复发放。
- 每次跨过结算点只执行一次；若单次批量 tick 跨过多个结算点，按结算点顺序逐次执行，保证与逐 tick 运行一致。

#### 金额与记账

```text
treasury = region.group.ledger.balance(Gold)
payout = treasury * 0.10
```

- 无现任国王、地区不存在、国库余额不为正时跳过，不产生零金额流水。
- 先从 `LedgerRef::Region(camp_id)` 扣除，再向 `LedgerRef::Personal(king_id)` 增加，并同步 `agent.carried_gold += payout`。
- 新增 `TransferReason::RoyalPrivy`（或等价中文标签“内帑”），流水必须包含 tick、地区、国王 Agent ID、金额、来源和去向。
- 该笔黄金进入随身携带量，后续沿现有回家卸货逻辑可沉淀回家户账本；不要直接写入家户余额，否则会失去“国王个人账户/随身黄金”的可观察语义。
- 国王更替不追溯补发：每个结算点只按结算时刻的现任国王执行。

#### 前端

王国大盘增加“最近一次内帑 / 累计内帑”字段；国王 Inspector 的随身黄金能够看到该收入。地区流水抽屉可按 `RoyalPrivy` 筛选，显示“地区公仓 → 国王个人”。

## 4. 跨模块技术落点

| 能力 | Rust 内核 | WASM/快照 | 前端 |
|---|---|---|---|
| 决策顺序浏览器保存 | 不新增模拟字段 | 不需要快照字段 | `decision-viz.js` localStorage 读写、校验、恢复默认 |
| 启动存档门禁 | 现有 save/load 契约 | 启动前不调用 tick | `save-ui.js` 启动层、浏览器能力检测、句柄状态机 |
| 流拍率 | `World3DEngine`/拍卖状态累计计数，存档持久化 | `WorldSnapshot` 输出统计 | `auction-ui.js` 统计卡与历史明细 |
| 房源切换稳定性 | 无 | 无 | `auction-ui.js` keyed DOM + 事件委托 |
| 最富家户 ID | 无 | 现有 household balances/id 足够 | `render_hud.js`、`ledger-ui.js` |
| 采集直达市场 | `decisions/market.rs`、`seeking.rs`、路由掉头 | 无新增字段 | Inspector/流水文案 |
| 国王内帑 | `region.rs` 结算、`journal.rs` 新事由、world save | region journal/统计快照 | `ledger-ui.js`、国王 Inspector |

涉及 Rust/WASM 的字段变更必须遵守快照三处同步、存档版本迁移、WASM 双副本复制和确定性 RNG 不新增消耗约束。

## 5. 实施顺序

### 阶段 A：无内核风险的前端稳定性与浏览器配置

1. 决策顺序 localStorage 化与恢复默认。
2. 启动文件门禁、Chromium 能力检测和权限错误处理。
3. 拍卖 active 房源 keyed DOM 重构。
4. 最富家户 ID 与现有家户均值展示。

### 阶段 B：拍卖与市场可观测性

1. Rust 拍卖场次累计计数、保存/加载和快照字段。
2. 拍卖大盘流拍率卡片及旧存档兼容提示。
3. 采集断流的原地掉头至市场与远程结算。

### 阶段 C：王国财政

1. 新增内帑流水事由和个人余额记账路径。
2. 100 秒结算时钟、存档恢复和高倍速跨点处理。
3. 王国大盘、国王 Inspector、流水抽屉展示。

每个阶段完成后分别运行 `cargo build -p sim_wasm --target wasm32-unknown-unknown --release`、双副本同步、`cargo test --lib`、`node tools/test-wasm.js`、`node tools/config-check.js`，并补充对应 `docs/current/` 机制文档与 changelog。

## 6. 验收标准

- 浏览器刷新后决策顺序保持；删除 localStorage 后恢复默认；非法值不会污染模拟。
- 未建立 `.json` 存档文件时无法开始游戏；取消选择、权限错误、Firefox 均保持阻塞态。
- 流拍率分母只增加已结束场次；成交/流拍计数恒等式成立；存档读回后不重复计数。
- 512× 下 active 拍卖房源连续切换 100 次无失败；成交/流拍后自动从列表移除且不显示残留详情。
- 最富家户展示稳定，金币并列时始终选择最小 household id。
- 水或粮现场发现所有野外 POI 关闭后，满足资金/体力条件的 Agent 直接平滑前往市场；不先回家、不瞬移；市场支付可从家户账本远程完成。
- 每 3000 tick 最多一次内帑结算；结算金额为当时地区公仓金币的 10%；流水来源、去向和国王 ID 正确；高倍速与逐 tick 结果一致。

## 7. 风险与回滚

| 风险 | 预防 | 回滚策略 |
|---|---|---|
| 浏览器存档门禁导致用户丢失旧 localStorage 世界 | 首次门禁提供“导入旧存档文件”入口，导入成功后再建立连接 | 暂时关闭门禁只允许读取已有文件，不恢复隐式 localStorage 启动 |
| 拍卖统计与历史档案不一致 | 以场次状态转移为唯一计数入口，前端只读 | 隐藏统计卡，不修改成交逻辑 |
| 市场重规划造成资源链路抖动 | 只在私有触发器全关闭且应急阈值满足时触发，并复用现有掉头 API | 关闭直达分支，回退既有返家后再决策市场 |
| 国王死亡/换王与结算点同时发生 | 固定 tick 管线顺序：先完成王位状态，再执行该 tick 的内帑结算 | 停发本 tick 内帑并记录诊断事件，避免错误转给旧王 |
