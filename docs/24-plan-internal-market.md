## 1. 设计目标与现状依据

让缺水缺粮的家庭有机会用积存的木材、石料和黄金换命；让水粮富余的家庭在木石金采集断流时，用自己的余粮换回建材或黄金。与旧方案（AMM 恒定乘积池）不同的是，**交易不再由买卖双方直接对池子报价成交，而是通过专门的场地充当中介、由雇佣的售货员（真人族人）撮合完成**——买家和卖家各自带着货物和需求到市场，售货员提供买卖报价、主持撮合、收取佣金作为主要收入来源。

典型故事：甲家缺水，但有一袋石料；乙家有余水，却找不到石料。甲把石料背到市集挂出卖单想换金子，乙随后也到市集挂出卖水的单子。售货员发现这两单可以以合理价格配对，撮合成交：甲的石料通过售货员换成金子，再用金子向乙买水；售货员抽一整个过程作为佣金。双方不必同时到场挂单，仍未匹配的挂单留在订单簿继续等待有缘人。市场不能解决全社会已经没有水粮的物理短缺，也不保证没资产的人都能获救；无偿救济仍由现有社会互助机制承担。

### 1.1 与当前实现的关系

- 当前外部榷场只向居民出售水、粮、木，支付黄金流向外部；支付支持家户账本与随身黄金协同。详见[外部市场现状](./current/16-market-pricing.md)。
- 当前采购已经下沉为水粮木资源意图的 L2 策略；以[决策现状](./current/06-motivation-ai.md)及 `decisions/market.rs` 为依据，不能照旧市场文档复活独立 b15 商贸需求。
- 家庭储备唯一真相源是家户账本，行囊是已经提取并正在搬运的物资。本文不恢复房屋 pantry 仓库。
- 本方案在现有决策框架上增加**集市场地实体 + 售货员 Agent + 订单簿系统**，不改马斯洛需求的意义，不新增全图扫描后强制派遣的"救命管理器"。

### 1.2 与 AMM 方案的关键区别

| 维度 | AMM 旧方案（废弃） | 售货员撮合方案（本文） |
|---|---|---|
| 价格机制 | 恒定乘积公式 `X × G = k`，确定性数学曲线 | 买卖双方分别报价，售货员按价格优先/时间优先撮合 |
| 做市主体 | 池子本身按公式做市，不需要人 | 真人售货员充当中介，提供有限自营头寸改善流动性 |
| 值守成本 | 无 | 售货员脱离生产，定期领取佣金 + 自营利润作为报酬 |
| 价格发现 | 完全由池比机械决定 | 由买卖双方报价意愿 + 售货员判断形成，更接近真人集市 |
| 黄金去向 | 池内循环 | 卖家黄金到手，售货员抽佣，剩余黄金留在买卖双方之间 |
| 可解释性 | 价格背后是数学 | 价格背后是人与人的行为，易叙事、易观察 |

> 为何放弃 AMM：AMM 虽然数学清晰，但需要"有限开局资本"冷启动，而且恒定乘积的价格曲线在需求量小的 early game 容易偏离直觉（"为什么我卖了一袋金子和昨天卖了一袋金子收到的钱完全不一样？"）。售货员撮合在人类学真实度、涌现叙事、"差价压力转化为售货员经营行为"上更强，符合本项目"让买卖体现为人与人的行为"的定位。

## 2. 谁在什么情况下交易

### 2.1 濒危交换：木石金换水粮

触发来自原有解渴、觅食或家庭水粮储备需求。人物已经进入饥渴警戒，或预计现有补给撑不到下一次正常获得水粮的时刻时，内部市场成为候选策略。不能等生理值归零才启动，也不能机械要求全图所有水源都枯竭：存在水源但赶不到，同样需要求生选策。

可行性必须在策略内部完整检查：

1. 人物在世、非胎儿且有自主交易资格；水粮缺口尚未被行囊、在宅可食用储备或可及时到达的自然点解决。
2. 有本人可出售物资，或有权在家提取家户物资；有可达市集、预估订单簿中存在可匹配卖单、预算有成功希望。
3. 将回家、装货、赴市、结算等待全部计入首次获得水粮的时间，并留安全余量。家中有钱不等于途中可用。
4. 在可活着到达的方案中，先满足最紧迫生理缺口，再考虑成本与返程储备。更便宜但赶不及的市场不可胜出。

出售候选为石、木、金，按满足最低救命量所需的资产牺牲选择组合：默认先用无近期用途的石料，再用超过供暖/修缮保留量的木材，并与黄金采购方案比较。不得仅因"有石头"便倾销全部建材。危机尚未解除时，每次只出售足以支付下一笔有效救命购买的数量。

若黄金更便宜或运输更及时，可以直接携金采购；黄金始终是支付媒介，"出售黄金"在玩家语义上就是花黄金买资源，不另造黄金商品价格。

### 2.2 反向交换：余水余粮换木石金

木、石、金的储备需求仍由既有意图产生。首期仅在该人物对目标资源没有可达且触发器开放的采集点，且家中水或粮存在可出售盈余时，选择内部交换。木、石、金任一品类断流即可，不要求三种一起枯竭；目标资源在市场订单簿中也必须有可匹配买单（参考售货员提供的深度信息或仅凭经验判断）。

自然资源"枯竭"与市场"缺货"是两个判据：森林采不到木，但市集有人卖木，才存在交换价值。黄金采集断流时，可卖水粮获取他人挂单的黄金；市集不会因为缺金而发行货币。

家庭出售上限按人口和预计耗用计算：

`可出售量 = max(0, 家户余额 − 保护储备 − 已承诺未提取量)`

保护储备统一按[融合设计 §2](./25-plan-system-integration.md#2-家庭资源保护与可支配余额)计算，取具备补货资格成员的有效停止阈值最大值（不低于基准）与家庭安全期耗用估计两者的较大值；记忆增量不能被出售忽略。明确待结事务只计入预约，不能同时作为预测耗用重复扣除。预测使用游戏时间和现有消耗参数，不把现实秒直接当作游戏小时。无可靠预测的第一阶段采用保守阈值，不假设"每户需求相同"。

普通交换只有超过保护储备及出售启动余量才启动，余额降至保护线便停止；使用滞回与失败冷却，避免"卖到短缺 → 马上补货 → 再出售"。任务结束后实际买入量达到原需求目标即退出，不因行情有利而无限贸易。b13 积累财富仍保留原有住宅等级等守卫，不以卖水粮绕过它。

### 2.3 家庭权限与救急边界

- **常规交换**：首期沿用家户户主支配家庭资产的规则。
- **紧急自救（本方案明确新增的权限）**：有自主行动能力的成年家庭成员可在家提取一笔受限救命预算；仅用于本人水粮自救与必要返程量，不获得无限支配家财权限。非户主使用这项权限必须留下用途、原家户与预算记录。
- **同户协同**：同一时刻至多一笔有效的市场提货任务；使用[融合设计 §3](./25-plan-system-integration.md#3-共用事务预约与任务占用)的共享预约，与做饭/投资等承诺共同校验余额，不能锁住全家其他活动。预约只限制尚未提取的余额，不计作第二份库存。其他成员可消费救命水粮，不能为保全交易预约而饿死；消费导致预算不足则缩单或取消。
- **无家户者**：成年人物可用合法持有的随身物资自救，不凭空获得家户提货权；该权限作为拟新增能力实现。儿童和胎儿首期通过家庭补给及已有照料/救济受益，不单独远行经商。
- **濒危变卖底线**：石料、黄金可突破普通储备保护；木材仍保留安全期供暖最低量。若还救不起，明确记录"保留供暖后资产不足"，不暗中扣走全家的最后燃料。

## 3. 集市场地与售货员本体

### 3.1 集市场地实体

首期全图只设一个独立**集市场地**，接入一处营地附近的可达路网，所有居民都能步行抵达。

| 维度 | 外部榷市 | 内部市集（拟新增） |
|---|---|---|
| 场地类型 | POI `Market`，系统所有 | `Marketplace`，制度公产，归属 Region（空地区则归世界）|
| 库存机制 | 三级被动再生 + 幂律定价 | **订单簿动态库存**：由买卖双方挂单形成 |
| 值守售货员 | 无（系统自卖自买） | **1–2 名人类售货员**（受雇族人）|
| 买卖方向 | 居民用黄金单向买水粮木 | 四类资源（水/木/石/粮）双向与黄金交换 |
| 黄金流向 | 流出本地经济（Void） | **留在居民间流转**：卖家到手、售货员抽佣 |
| 经营维护 | 无 | 售货员佣金为主要收入；自营补充流动性 |

集市场地不复用外部 `Market` 的再生逻辑，也不混入免费采收 `NodePool`。先验证单市集闭环，再考虑多市集（会引入地区价差与运输贸易，属于后续范围）。

### 3.2 售货员的生命周期

#### 3.2.1 选拔

售货员从**世界中的在世成年族人**中选拔，按综合分排序：

```text
clerp_score = 气场(charm) × 0.5 + 智力(intelligence) × 0.5
```

- 每 600 tick（10 游戏小时）扫描一次世界，综合分排名最高且当前没有售货员岗位担任者的族人进入候选池；
- 候选池人数 ≥ 当前空缺岗位数时，按分高低选齐；职业条件还包括：年龄 ≥ 18、当前非孕期、当前非囚禁/征战状态；
- 入选者脱离原家户（户主不变，但其本人身分转为"制度雇员"），入住集市场地附属宿舍；
- 首期仅 1 个售货员岗位，后续可随市集规模扩张增设（每增设 1 摊 +1 岗）。

> 为何要"脱离原家户"：售货员的主要劳动时间都在市集值守，不应同时参与家户采收囤货，否则会与家户委托人构成利益冲突（"帮是自家人卖高价好还是帮外人卖高价好？"）。脱离家户使其**唯一收入 = 佣金 + 自营利润**，把它的利益与"撮合成交量"严格对齐。

#### 3.2.2 任期与退休

- 每届任期 12,000 tick（约 8.3 游戏天）一循环；任期结束时，如果市场仍正常营业，重新走§3.2.1 选拔流程，让更符合条件的后来者接班；
- 任期超过 60 岁的售货员不再续聘，由系统重新招聘；
- 任期内的售货员因死亡、重病、丧失生活能力（衰弱/囚禁）等原因无法继续值守时，立即解聘并触发替补招聘；
- 售货员退休后**回归原家户**或按既有单身户处理规则安置；退休时在任期内积累的自营利润已归当时家户（见§4.3）。

#### 3.2.3 日常行为

售货员每天（游戏内）做的事：

1. **维护订单簿**：接收到场者的挂单委托，标记状态（pending/matched/cancelled）；
2. **主持撮合**：按§4 的买卖优先、时间优先规则发现可匹配的买卖对，执行结算（库存与黄金双边交割，自身抽取佣金）；
3. **自营做市**：在订单簿流动性不足时（如某资源连续 200 tick 没有对手单），可以按规则挂自营买卖单（头寸上限见配置），通过低买高卖赚取差价；自营单优先度低于用户挂单；
4. **报告行情**：每隔 200 tick 在场内公告当前"买一/卖一/24 小时成交量/流动性评级"，供来往行人参考。

## 4. 订单簿撮合与定价

### 4.1 订单簿结构

市集内每个资源品类（水、粮、木、石）各维护一张独立的**限价订单簿**：

```rust
pub struct Marketplace {
    pub venue_id: PoiId,             // 集市场地 POI 编号（单一世界仅 1 个）
    pub region_ownership: Option<RegionId>, // 归属地区（空则为世界）
    pub clerk_id: Option<AgentId>,   // 当前售货员（无则休市）
    pub books: [OrderBook; 4],       // 0:水 1:粮 2:木 3:石
    pub commission_bps: u16,         // 佣金率（基点，100 = 1%），含买卖两腿
    pub clerk_holding: ResourceBundle, // 售货员自营头寸（上限受配置约束）
    pub status: MarketStatus,        // 开市/休市/关闭（资本＝卖家挂单总额）
}

pub struct OrderBook {
    pub resource: ResourceKind,      // Water/Food/Wood/Stone
    pub bids: Vec<Order>,            // 买单：价格降序（最高买价在前）
    pub asks: Vec<Order>,            // 卖单：价格升序（最低卖价在前）
    pub last_price: f32,             // 最近成交价（展示与参考）
    pub volume_200tick: f32,         // 近 200 tick 成交量（流动性评级）
}

pub struct Order {
    pub order_id: u64,              // 全局唯一（稳定 ID）
    pub party: OrderParty,          // 挂单方（卖家/买家身份 + 家户 + Agent）
    pub price: f32,                 // 单价（金/资源单位，限价）
    pub quantity: f32,              // 挂单量（资源单位）
    pub filled: f32,                // 已成交量
    pub placed_tick: u64,           // 下单 tick（时间优先判据）
    pub state: OrderState,          // Pending / Partial / Filled / Cancelled
    pub affinity_benefit: bool,     // 是否已享受信任折扣（-4 以上才可选）
}
```

订单簿是**市场资产的唯一真相源**：已挂出但未成交的买方黄金、已挂出但未成交的卖方货物分别**挂起冻结**（买方：家户账本黄金转入"市场冻结"；卖方：家户账本/行囊资源转入"市场冻结"），不能挪作他用。成交后黄金与资源真实过户并释放冻结；撤单后返还原主。

### 4.2 撮合规则

每 1 个 tick 内，售货员执行：

1. **收集新单**：从到场交易者处接收委托（挂单/撤单）；
2. **发现交叉**：若买一价 ≥ 卖一价，则存在成交可能；
3. **匹配优先级**（严格顺序，确保确定性）：
   - 价格优先：买方出价越高越优先，卖方要价越低越优先；
   - 时间优先：同价位下先下单者优先；
   - ID 破平：仍相同则按 `order_id` 升序；
   - **信任折扣优先**：同价下，具有 `affinity_benefit: true` 的单子优先（体现"照顾朋友"）；
4. **成交量**：双挂单中较小量为本次成交量；
5. **结算价**：（买价 + 卖价）/ 2（体现被动方让步，首期不引入滑点扩展）；
6. **佣金**：卖方实际到手黄金 = 成交量 × 结算价 × (1 − `commission_bps`/10000)；售货员所得 = 成交量 × 结算价 × (`commission_bps`/10000)；买方已付款不退。

每次撮合后：
- 双挂单 `filled` 增加，状态按剩余量更新；
- 买卖双方真实资产过户（买方黄金 = 量×结算价，卖方货物 = 量；卖方额外收到扣除佣金的黄金）；
- 售货员`clerk_holding`中"佣金黄金"部分增加；
- 卖单/买单剩余量 0 → 移至 `Filled`，从活动簿移除；
- `last_price` 更新。

### 4.3 售货员自营与报酬

售货员报酬来自两路：

| 来源 | 机制 | 用途 |
|---|---|---|
| **撮合佣金** | 每次成交抽 `commission_bps`（首期建议 30 BPS = 0.3%，可调）| 售货员个人家户金库 |
| **自营做市** | 库存≤上限时按规则低买高卖 | 售货员个人金户（承担库存贬值风险）|

自营规则：
- 自营头寸上限 = `ClerkHoldingCap`（配置，各品类单 20 单位）；
- 仅在订单簿某资源连续 ≥ 200 tick 没有对手单时才允许自营（防止过度干涉自由定价）；
- 自营买价 = `last_price × (1 − clerk_spread_bps/10000)`，卖价 = `last_price × (1 + clerk_spread_bps/10000)`；
- 自营单优先级**低于**所有用户挂单；
- 售货员不计佣金，差价自营利润 60% 归售货员家户，40% 留存市场资本（为将来储备）。

售货员**每日基础消耗**（体力的/水分/食物）按普通成年工人规则走，由售货员家户账本支付。

### 4.4 交易中的好感度信任折扣（爱好感度系统）

详见 [31 好感度 §6](./31-plan-affinity-system.md) 决策层接入；本节给出市集侧的契约接口：

- 买卖双方在挂单位检查"双方好感 ≥+4"时，自动可选 `affinity_benefit: true`（按钮默认开启）；
- `affinity_benefit: true` 的单撮合优先级上升；且有机会在"多卖单同价"时优先匹配好友挂单；
- 首期不做"信任免佣"等复杂扩展，仅做排序优先；
- 好感度 ≤ −4 时售货员有权**拒绝撮合**（关系太差不做对手盘），返回失败原因 "对方怨怼，售货员拒绝撮合"；
- 拒绝撮合不扣资产，不挂单；双方按其他策略（采收/外部采买）重新走。

### 4.5 实物换实物通道

`出售 A → 获得黄金（扣佣金）→ 买入 B` 由市集自然支持——同一人到市先挂卖单、成交后立刻挂买单，两腿独立在订单簿中撮合；不保证原子性（第一腿成交后第二腿可能无法按预期价成交），这也是售卖货员判断与风险的一部分；但两腿"跨品类结算由黄金中介"在操作层面统一，不需要虚拟的"A→B 直接兑换率"。

## 5. 搬运、执行与记账

### 5.1 一次内部交易的完整过程

`资源需求 → 选择内部市集 → 必要时返家 → 装载出售物 → 前往市集 → 重报订单簿 → 手工挂单或看即成交 → 等候撮合/即成交 → 取货或结算黄金 → 返家卸货`

- 在家装货时，按物理装载速率从家户账本扣除并加入行囊；预约本身不扣账。沿用每类独立容量，不能把四类 50 单位误当作共享 50 单位。
- 家户来源货物必须到家提取且装载成功后才可出售；无家户者的合法随身物资或已有明确本人处分权的货物可直接到市，无须先回不存在的家。
- 交易优先使用本次授权货物，避免顺手卖掉另一个生存任务留下的口粮。
- **在市集挂单后，等待撮合**：可能立即成交（对手盘价格 ≥ 你的卖价），也可能一直不成交；挂单者可主动撤单或降低卖价；撮合成功时市集通知挂单者取货结算；"当场自杀"式的极端需求支持直接挂"市价单"（接受当前买一价立即成交，首期可以仅支持限价单，市价单 P2 再加入）。
- 返回家宅后按正常卸货规则入账。未卖出的货物随身返回，不能在取消任务时直接加回家户账本。
- 若同品类出售后又买回，拒绝作为单任务计划；无有效收益需求或无可成交项即退出，不在市场无限驻留。

### 5.2 事务与守恒

建议增加内部市集账本引用、取货/退货原因、内部成交流水及售货员佣金流水；具体类型名实施时确定。

| 事件 | 源 | 目的 | 守恒要求 |
|---|---|---|---|
| 家庭提货 | 家户账本 | 人物行囊 | 家户减、行囊同量增 |
| 挂出卖单 | 人物行囊/家户账本 | 订单簿冻结 | 真实资产进入冻结状态 |
| 撮合成交（卖方侧）| 订单簿卖方冻结 | 卖方黄金（扣佣）+ 卖方行囊/账本（货物已转） | 买方黄金 + 卖方货物强守恒 |
| 撮合成交（买方侧）| 订单簿买方冻结 | 买方行囊货物 | 同上 |
| 售货员佣金 | 成交金额 | 售货员家户金库 | 佣金总量 = 成交额 × 费率 |
| 售货员自营利润 | 自营头寸差价 | 售货员家户（60%）+ 市场资本（40%）| 资金严格过户 |
| 撤单返回 | 订单簿冻结 | 原owner行囊/账本 | 不减不增 |

内部市集不新增全世界黄金，也不销毁黄金。水粮等只有真实生理消费、既有耗用和将来明确实现的损失会减少；外部采购按原规则单独统计出入世界的流量。

### 5.3 中断与社会关系变化

- 途中被更高需求抢占：释放未成交挂单（资产退回家户/行囊），保留已携带货物，以当前位置平滑改道；不重置订单簿或瞬移回家。
- 人物死亡：取消挂单和预约，随身物资只走既有死亡资产处置一次，不再以"订单退款"复制回旧家户。若既有处置会消耗物资，记录实际损失而非假定全部继承。
- 家户解散、分家、改嫁：失效的未执行挂单立即取消并退回未成交货物；已成交的货款按婚姻/分家时点拆分结算，不保留指向已解散家户的扣账引用。
- 订单簿挂单超过 `OrderLifespan` tick 仍未成交：标记为 pending-expired，由售货员主动通知挂单者，允许续期一次；续期仍不成交则自动撤单。
- 返程中家宅消失：目的地重新按当前合法归属选择，行囊物资不因此清零。

## 6. 黄金与外部市场如何比价

与采收、记忆、禀赋和家资偏好的组合统一遵循[融合设计 §4](./25-plan-system-integration.md#4-统一-l2-选策与记忆接入)。本节提供真实报价与时间，不另建采购仲裁器；下文普通成本排序是未施加有限偏好的基础次序，危机排序不受偏好改变。

"黄金比价"比较的是**同一份黄金能在内外两市买到多少目标物资**，而不是创造第二种黄金汇率。只对双方共同提供的水、粮、木比较；石料没有外部采购报价，黄金本身也没有可向外部出售的独立商品行情。

对相同目标量 `q` 计算：

- `C_in(r,q)`：内部按**当前订单簿卖一价**加上佣金率算出总黄金成本；若卖单深度不足，按多个卖单加权平均计算（买方需承担"大单打穿深度"的实际边际损失）。
- `C_out(r,q)`：按外部现有逐笔成交、自救规则、库存变化与黄金扣减逻辑逐笔模拟出的成本。
- `T_in / T_out`：当前位置到首次获得救命量的预计游戏时间；内部包括回家、装货、**挂单等待撮合时间**（估计值 = 当前订单簿成交量越快越短），外部沿用既有远程黄金支付优势。

先排除超出存活时间、库存不足、预算不足或不可达的路线。危机下按"及时获得最低救命量 → 更早获得 → 更少牺牲家庭资产"排序；常规交易比较同量成本，再以路程和固定 ID 打破平局。用于维持原目的地的价格切换滞回只约束普通交易，不能阻止危机抢占。

外部报价只供选策，不直接改内部订单簿。人物可以先在内部卖木石筹金，再赴外部买水，但两地之间不能原子结算：必须实际携金赶路，承担价格变化和耗时风险。

## 7. 决策与数据接入边界

L1 继续回答"解渴、觅食、储备木石金"；L2 比较自用、采收、外部采购、内部交换；L3 执行回家、装货、行走、成交、自用和卸货。执行中的交易计划存入 `ActiveTask` 及其策略阶段，通过统一 transition 入口推进，不能另造与之竞争的状态机。

不属于瞬发意图：前往市集、挂单、等候、撮合都是持续任务。维持现有错峰决策、固定 dt 与 tick 阶段，不新增一个市场线程自行决定居民去向。

建议持久化以下最小状态：

| 所属 | 状态 |
|---|---|
| 市集 | 稳定 ID/地点/归属、售货员 ID、订单簿各状态（挂单/冻结）、累积统计（手续费、自营利润、成交量、last_price）|
| 交易者 | 联系挂单 ID 列表、普通出售滞回、失败冷却；已挂单货物仍归冻结而非家户现货 |
| 售货员 | 任期 tick、自营头寸记录、佣金累计、职业冷却 |
| 家户 | 共享预约记录中的唯一市场提货预约及剩余额度、失效判据 |

报价是从订单簿重算的只读结果；出发时信息仅作计划，不能作为到场成交承诺。首期允许沿用全局只读市场信息供选策，这属于模型简化，UI 应标为"预计"；后续记忆或信息传播可以改变已知行情，但不能改变真实成交余额。

全部影响行为的状态须随档持久化，读档不能重发启动资本、重提货、重成交或丢失半段任务。快照新增字段按 `snapshot.rs → world_snapshot.rs → snapshot_bin/encode.rs → snapshot-bin.js + rustworld.js` 同步，涉及枚举还要同步二进制字典。应用版本和存档格式如何升级由未来实现时按实际结构变更决定，本规划不改变当前版本或存档兼容性。

新增参数集中进入既有配置体系：开局闲置资本、佣金率、自营头寸上限、挂单失效时长、售货员任期长度、每营地摊位数、高低背景提示。优先复用已有生理警戒、容量、耗用与运输参数，不维护另一套冲突的默认值。

## 8. 玩家如何看懂市集

市集 Inspector 展示四品类的订单簿快照：买一价 / 买一量；卖一价 / 卖一量；最近 24 小时成交条数与价格柱状图；售货员头像、任期、当日佣金收入。

行情统一使用"金/单位"，同时提供"当前卖出 X 单位实际可得"与"当前买入 X 单位实际花费"两个参考计算器，不能只展示订单簿边缘价格让玩家误判。

人物卡解释本次行动：

- "缺水，家中有石，携 12 石去市集挂单换水"
- "家中余粮，金矿断流，售余粮给市集，得金 6"
- "市集缺木，排队等木 1 游戏小时"

成交记录保留买卖双方家户、输入品类/数量、实际结算价、佣金、现场消费、订单编号；一笔挂单成交关联撮合记录和对手方（匿名），防止被看成两笔独立获利。明确展示挂单未成交、缺货、预算不足、路线来不及、行情变动等失败原因。

宏观观察售出清单最富黄金家户；净买入生存物资家庭比例；濒危交易后存活情况；订单簿成交量与售货员佣金收入。"救急成交"不是"成功救命"，必须观察交易后的生存结果。

## 9. 决策分支与好感度接入（读好感度系统）

详见 [31 好感度 §6](./31-plan-affinity-system.md) §6 与 P1 阶段；本节给出市集侧的契约接口：

- 好感度 +4 以上：挂单时可选 `affinity_benefit: true`，撮合排序上升（朋友优先成交流）；
- 好感度 −4 以下：售货员拒绝撮合，返回失败原因，双方改走其他通道；
- 好感度变化事件源：`卖出撮合成功 +1`（频繁交易会自然熟化）、`毁约/撤单归咎 −1`
- 售货员本身也参与好感度网络：频繁成交的家户与售货员之间也会缓慢积累亲密度（体现"熟客关系"）

## 10. 实施阶段与验收

| 阶段 | 范围 | 完成条件 |
|---|---|---|
| P0 场地与订单簿 | 单市集四类限价订单簿（买卖侧各一条即可）、售货员 1 人、佣金撮合、守恒 | 演示账目可复算，黄金守恒，无零库存除法 |
| P1 最小生存闭环 | 家户提货 + 濒危木石金换水粮 + 现场救灾 + 外部比价 | 至少一个濒危家庭实际携货挂单、撮合成交、自救并带余货回家；好感度~-4 拒绝撮合生效 |
| P2 双向资源循环 | 余水余粮换木石金 + 家庭保护 + 信任折扣 + 好感度反馈接入 | 断流资源需求能通过居民挂单解决，出售不导致机械补货震荡；好感度差异改变交易流向 |
| P3 长程平衡 | 多季节多代、佣金敏感性、财富分配、多市集扩展 | 结论区分售货员做市效应、再分配效应与外部进口效应 |

实施时至少验证：

1. 无金有木/石家庭能完成挂卖单→撮合→得金→挂买单→买水→自救回家；若匹配失败，挂单资产全部不变。
2. 富余水粮家庭在木/石/金分别断流时可挂卖单换金，家庭保护量不被突破；无需求时不纯粹倒买倒卖。
3. 订单簿无水/无粮/黄金触及下限/容量不足/极小挂单/大单吃深度均可有限步退出，无负余额、NaN 或虚空补货。
4. 相同目标量下内外成本比较准确；更便宜但来不及的路线不被选中；挂单作废后资产真实释放。
5. 同户多人取货、途中死亡、分家、家户解散、家庭吃掉预约和途中存读档，均不超额取货、不重复结算、不遗留永久挂单。
6. 所有封闭交换循环在无外部干预下收益不为正（售货员佣金为唯一泄漏，属合理成本）；每次交易前后逐资源核对行囊、家户、市场冻结、成交和明确外部流量。
7. 同种子、连续/分批推进、存读档续跑保持确定性；只读报价/观察不消费 RNG，不修改余额或缓存中的行为状态。
8. 对比"无内部交易""同量物资保留在家庭/公仓""市集撮合"三组，控制初始总资源与黄金一致；观察多季节、至少三代的死亡率、家族存续、财富集中、救急后存活与内部成交比例。单列灭绝样本，不把灭绝当作财富均衡。

按项目要求只使用临时经济验证脚本验证公式与极端场景，实施阶段完成后删除；长期回归复用既有 WASM、确定性、快照、配置与前端门禁。性能以同种子同规模基线配对，报价只在决策/交易发生时计算，避免每 tick 全人口扫描全部市场或全量重新寻路。

首期只交易水、普通粮、木、石与支付黄金；做饭/狩猎新增的熟食和生肉不自动混入粮池，也不自动扩池。家庭可食用储备、供暖预测和货物身份遵循[融合设计 §5](./25-plan-system-integration.md#5-食物用品与身体状态)，同一份物资不得同时算原粮与熟食。

## 11. 首期明确不包含

信用借贷、负库存、凭空铸金、自动按外部价强制钉住订单簿价格、多摊售货员主动对敲、随时赎回公共资本、独立套利机器人、跨营地多个内部市集、无偿救济和新的税收政策都不在首期。它们会改变风险、分配或流动性约束，后续必须单独设计，不能以"完善市场"为由隐式加入。

本方案最终希望形成的是：家庭积累的建材可以在危机时换来生存，幸存家庭的余粮又能换回生产资料；真人售货员在场地里提供报价、主持公允、赚取佣金；好感度在撮合排序与拒绝守卫中表达为真实的亲疏远近。
