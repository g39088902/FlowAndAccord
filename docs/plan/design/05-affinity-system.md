# 05. 人际好感度系统设计规划 (Affinity System Plan)

> **状态**：规划设计 / 设计稿，尚未实现、未排期；不描述当前运行行为。文中类型、字段与数值均为建议规格，落地前以对应局部 AGENTS.md 与源码为准。
> **整理日期**：2026-09-10。
> **定位**：为每名 Agent 引入一张**有限容量、有界取值的人际态度表**——对最多 36 个具体的人维持 -7~+7 的好感度，作为「事件性记忆」（[02 记忆](../tech/02-memory-system.md)）与「瞬时情绪」（[04 激素](./04-hormone-system.md)）之上长期聚合的态度层，为[关系 × 生产](./03-social-relations.md)各方向提供统一的关系数值底座。

## 1. 设计目标与分层定位

### 1.1 解决什么问题

当前世界里人与人的关系只有**结构性**的（婚姻、血缘、宗族、王国辖属），没有**个人性**的：两个族人之间「处得怎么样」没有任何表达。23 号记忆方案解决了「他经历过什么」，但记忆是事件性的、按 `(kind, subject, resource)` 合并键组织的，不适合直接回答「他对张三的总体态度」。本方案补上这一层：**对具体某个人的、随事件累积漂移的标量态度**。

设计判据沿用 [03 号文档 §8](./03-social-relations.md)：好感度本身不派任务，只在决策分支的**候选排序、成本调制与守卫条件**里被读取；一切「因为好感度高所以去做什么」必须写在分支自包含条件内部。

### 1.2 三层关系信息的分工

| 层 | 载体（规划） | 特征 | 职责 |
| :--- | :--- | :--- | :--- |
| 事件层 | 23 号 `MemoryFact` / `MemoryEntry` | 有情节、有证据、可遗忘 | 记录「发生过什么」，是好感度变化的**原料** |
| 态度层 | **本方案 `AffinityLink`** | 无情节、有界、有限容量、长期稳定 | 回答「我对这个人的总体看法」，是决策读取的**结论** |
| 情绪层 | 30 号激素 | 瞬时、有余韵、随生理波动 | 调制本次好感度变化的**幅度**（如催产素放大正向增量） |

三层各司其职：记忆条目可以被遗忘而不影响已沉淀的好感度；激素水平回落后不回滚好感度；好感度变化不要求同时持有对应记忆（允许「说不出为什么就是看不顺眼」的聚合效应）。

## 2. 核心规格（硬约束）

以下为系统级不变量，任何实现与后续调优不得突破：

| # | 规格项 | 值 | 说明 |
| :--- | :--- | :--- | :--- |
| R1 | 单人容量 | **36 人** | 每名 Agent 最多维护 36 条对具体他人的好感度条目；超出即触发驱逐（§4） |
| R2 | 取值范围 | **[-7, +7] 的整数** | 15 个等级 + 0，共 16 档；变化按事件幅度整数加减，越界钳位 |
| R3 | 陌生人默认值 | **0（不存储）** | 对任何未建立条目的人默认 0；从未互动的人不占容量 |
| R4 | 溢出驱逐 | **丢弃 \|值\| 最小者** | 新条目使容量超过 36 时，驱逐绝对值最小的条目（关系最淡的先淡忘）；同分驱逐规则见 §4.3 |
| R5 | 确定性 | 无独立 RNG | 好感度的建立、变化、驱逐全部由事件与确定性 tie-break 规则驱动，不消耗 `WorldRng` |
| R6 | 随档持久化 | 是 | 好感度表是行为状态，随存档保存/恢复；快照走 FABS 全链（§7） |

**容量 36 的取值理由**：覆盖「配偶 + 子女父母 + 祖辈 + 旁系亲属 + 同营熟识 + 常打交道的交易对象」的邓巴式小圈子上限；初始 20 人部落内多数人互为熟人，36 留出繁衍增长与跨代联结的余量，同时强制「人越多元，能真正记住的人越少」的涌现压力——超出圈子的新 acquaintance 必须挤掉最淡的旧关系。

## 4. 数据模型与容量驱逐

### 4.1 建议数据结构

```rust
/// 单条好感度（设计稿命名，非既有 API）
pub struct AffinityLink {
    pub peer_id: u32,          // 对象 Agent 稳定 ID
    pub value: i8,             // -7..=7，钳位
    pub last_changed_tick: u64, // 最近一次变化 tick（tie-break 与观察用）
}

// 挂在 Agent 上（或 AgentId → BTreeMap<u32, AffinityLink> 的侧表）：
// capacity = config.affinityCapacity (36)，超限即驱逐
```

- 建议用 `BTreeMap<peer_id, AffinityLink>` 或按 `peer_id` 排序的 `Vec` 承载，保证遍历顺序确定（快照编码、驱逐扫描都依赖稳定顺序）；
- `value == 0` 的条目**建议删除**：回归陌路即释放槽位，避免「归零但占坑」挤占容量、也让「条目数 ≤ 36 且全为非零」成为可断言不变量；
- 衰减**首期不引入**（见 §9 开放问题 O1），`last_changed_tick` 仅用于驱逐 tie-break 与 UI「多久没来往」的展示。

### 4.2 变化流程

1. 事件结算点（如卸货入账、交易成交、目击偷窃）产生一条**好感度事件**（方向 + 幅度 + 对象 + 受体），由物理结算器产生，决策层不凭空生成；
2. 受体在自身表中查找 `peer_id`：无条目且 `value + delta == 0` 时不建条目；无条目且非零时新建（走容量检查）；有条目时 `value = clamp(value + delta, -7, 7)`；
3. 新建使条目数超过 36 时执行驱逐（§4.3），**驱逐发生在写入之前**——若新对象自身就是绝对值最小的条目，等价于新关系尚未沉淀就被淡忘，符合语义；
4. 写 `last_changed_tick = 当前 tick`。

同一事件对同一 `(受体, 对象)` 只编码一次；幅度建议以 ±1 为主、重大事件（救急赠予、抓获行窃、血亲死亡归咎）允许 ±2~±3，具体事件清单见 §5。

### 4.3 确定性驱逐规则（R4 细化）

容量超限时，驱逐候选按以下顺序比较，**逐级破平，保证任意输入下结果唯一**：

1. `|value|` 最小者驱逐（关系最淡的最先淡忘）；
2. 并列者中 `last_changed_tick` 更早者驱逐（同样淡，更久没来往的先忘）；
3. 仍并列者中 `peer_id` 较小者驱逐（稳定 ID 终裁）。

**禁止**引入遍历顺序依赖、哈希序或任何随机成分；驱逐不产生事件日志噪声（可选仅在 Inspector 中体现）。

## 5. 好感度事件源（候选清单）

> 首期只挑低成本、已有留痕点的事件接入；每个事件落地时须写明幅度与唯一结算点，禁止同一事实在多个入口重复计分。

### 5.1 正向事件

| 事件 | 建议幅度 | 结算挂点（现状/规划） | 备注 |
| :--- | :--- | :--- | :--- |
| 交易成交 | +1 | 售货场成交流水（售货员撮合、双方履约） | 频繁交易会自然熟化 |
| 救急赠予（赠方→受方） | +2 | 20 号方向④ 求助赠予 | 卸货真实搬运到账时计分 |
| 换工帮工完工 | +2 | 29-A4 分成流水 | 双向互记 |
| 成婚结亲 | +2 | 婚姻登记簿 | 双方全体在世父母/子女各 +1（结亲外溢） |
| 共同劳作（同 POI 同时段采收） | +1（低频限次） | 生态交互结算 | 需限频防刷，如同 episode 至多一次 |
| 借出工具按时归还 | +1 | 29-A5 借还流水 | 逾期/损毁走负向 |

### 5.2 负向事件

| 事件 | 建议幅度 | 结算挂点 | 备注 |
| :--- | :--- | :--- | :--- |
| 目击行窃（受害者） | -3 | 29-B6 抓获判定 | 唯一允许的高幅负向之一 |
| 目击行窃（第三方） | -1 | 同上 | 名声外溢 |
| 竞拍失败对赢家 | -1 | b17 拍卖结算（29-§5 拍卖宿敌） | 只对最终赢家 |
| 拒绝求助（被拒方视角） | -1 | 20 号方向④ 求助判定 | 有能力却拒绝才计分 |
| 交易毁约/断流空跑归咎 | -1（低频限次） | 售货场履约流水 | 设计稿保留，防滥用待定 |
| 血亲死亡归咎（若未来引入可归因死亡） | -3 | 18 号战斗结算 | 接「不共戴天」的来源，需长程存活实验验证 |

### 5.3 初始化偏置（非事件）

初次见面不是白纸：建议在**首次建立条目**时叠加结构关系偏置——同宗族 +1、直系血亲直接 ≥ +4（如亲子女 +6、父母 +5、祖孙/同胞 +4）、配偶 +6；负向初始化仅保留世仇宗族 -2（29-B5 预留）。偏置同样受 R1~R4 约束。

## 6. 决策层接入（只读调制，不派任务）

好感度是**结论层**，决策分支在候选比较时读取它做三类事：

1. **候选排序调制**：求助对象、换工对象、售货员撮合市场交易双方、b16 求偶候选的排序键中加入 `affinity(peer)` 分量（范本：`B16Courtship` 的「魅力 → 距离 → ID」择偶序，好感度作为新维度插在合适位置）；
2. **成本/收益调制**：好友交易享受信任折扣（接 24 信任折扣）、仇隙以上拒绝交易或要求溢价（29-B5 世仇加价的数值底座）；
3. **守卫条件**：+6 以上才可参与救急赠予、-4 以下拒绝一切协作、-7 前置于暴力冲突判定——全部写在分支条件内部，符合根 AGENTS.md §4.11.1「马斯洛引擎是唯一任务分派入口」。

**边界**：好感度不得改写需求层级、不得越过 L1 抢占矩阵、不得直接写 `state`/路线/pending；POI 私有施密特触发器仍独立裁决可用性，好感度只在「可用、可达」的候选之间表达偏好（与 23 号记忆同一边界）。

## 7. 确定性、存档与快照

- **确定性**：R5 已声明零 RNG 消耗；新增任何按 agents 顺序遍历的逻辑保持既有消费顺序契约，同种子逐字节一致必须通过 `node tools/test-wasm.js`；
- **存档**：好感度表随 `WorldSave` 持久化（逐条 `(peer_id, value, last_changed_tick)`）；因字段新增，`SAVE_FORMAT_VERSION` 手工 +1 并同步 `world_save.rs` 与 `save-ui.js`（根 AGENTS.md §4.9）；
- **快照四处同步**（根 AGENTS.md §4.5）：`snapshot.rs` 结构 → `world.rs` `generate_snapshot()` 赋值 → `snapshot_bin/encode.rs` 定长编码（每人 36 条 × 定长字段，建议只编码条目数 + 非零条目）→ `snapshot-bin.js` 解码 + `rustworld.js` `_applySnapshot()`；新增等级名须同步 `snapshot_bin/dict.rs` 的 `*_code()`/`*_table()`；同步核对 `node tools/snapshot-check.js`（JSON 对拍门禁已于 v1.50.33 随 JSON 快照通道移除）；
- **跨世界失效**：好感度表随 Agent 存亡，不设独立缓存，无 STR_TAB 式跨世界串味风险；读档重建后表内容从存档恢复，禁止用快照回写内存表；
- **死亡清理**：peer 死亡时条目去留二选一（见 §9 O2），落地前须定案并写入不变量；Agent 自身死亡即整表消亡（继承「对亡父印象」属 23 号 P3 传承，不在本表）。

## 9. 开放问题与后续决策

| # | 问题 | 当前倾向 |
| :--- | :--- | :--- |
| O1 | 是否引入时间衰减（久不往来自动降档） | **首期不做**。事件驱动已足够产生漂移；衰减会让「恩情恒久」的叙事消失，且增加 tick 扫描成本；若后续引入，须走确定性批量结算并重做确定性矩阵 |
| O2 | peer 死亡后条目保留（悼念/迁怒锚点）还是清除 | 倾向**保留但冻结**（不再变化），为 23 号「丧亲」记忆与可能的迁怒机制留锚；代价是占用容量，需观察长程挤占 |
| O3 | 双向对称还是单向独立 | **单向独立**（A 对 B 的好感 ≠ B 对 A 的好感）；单恋、单方记恨是涌现素材，对称化会抹掉它 |
| O4 | 幅度是否接入 30 号激素调制 | 倾向**是**（催产素放大正向、皮质醇放大负向），但作为可选叠加层后置，P0 阶段用固定幅度 |
| O5 | 36 容量是否随人口规模配置化 | 容量进 `SimConfig`（`affinity_capacity`，const 默认 36 三处同步），但不随人口动态扩张——固定上限才是涌现压力 |

## 10. 分阶段落地建议

- **P0 数据先行（行为零效果）**：表结构 + 事件编码（只接交易成交、成婚结亲、目击行窃三类）+ 存档 + 快照 + Inspector 只读展示；开启效果开关关闭时逐字节等价（先例：30 号激素效果开关）；验收 = 确定性矩阵 + 快照防漂移全绿；
- **P1 最小行为切片**：售货员撮合市场交易排序与信任折扣读取好感度（24 号 P1 落地后叠加）；验收 = 对照实验证明关系差异改变了交易流向；
- **P2 全事件源 + 协作门禁**：§5 全清单接入，换工/借出/救急赠予的守卫条件上线（依赖 20/29 对应方向落地）；
- **P3 敌对末端**：-6/-7 档接世仇（29-B5）与冲突判定（18 Phase 4），以「不击穿繁衍链条」的长程存活实验为最终验收（29-§8 红线 4）。

## 11. 设计红线

1. **零 RNG**：建立、变化、驱逐全确定性，不消耗 `WorldRng`（R5）；
2. **容量与有界铁律**：36 条 × [-7, +7] 是不变量，任何事件源不得绕过钳位与驱逐直接写值；
3. **只读调制**：好感度只进候选排序、成本调制与分支守卫，严禁借它派任务、写 `state` 或改需求层级（根 AGENTS.md §4.11.1）；
4. **事件单一结算点**：同一事实只在一个物理结算点计分一次，禁止决策层凭空生成好感度事件；
5. **快照与存档全链**：随档持久化、FABS 四处同步、`SAVE_FORMAT_VERSION` 手工 +1，缺一不可（根 AGENTS.md §4.5 / §4.9）。
