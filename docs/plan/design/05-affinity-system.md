# 05. 人际好感度系统设计规划 (Affinity System Plan)

> **状态**：规划设计，尚未实现、未排期；所有新增字段、参数和接口均为建议规格。
> **复核日期**：2026-09-13。
> **定位**：每名族人对最多 36 名在世他人保存 -7～+7 的有向态度，为已有决策提供偏好，不独立派发任务。
> **交付**：按本次要求，实施方案与任务序列导出至根目录 [AFFINITY_IMPLEMENTATION_PLAN.md](../../../AFFINITY_IMPLEMENTATION_PLAN.md)。该文件为本专项实施规划入口，尚不代表现状。
> **关联**：[记忆](../tech/02-memory-system.md) · [激素](./04-hormone-system.md) · [关系与生产](./03-social-relations.md) · [内部市场](../tech/03-internal-market.md) · [融合契约](../tech/01-integration-contracts.md) · [当前决策引擎](../../current/tech/11-decision-engine.md)。

## 1. 设计目标与分层定位

结构关系回答「是否是配偶、亲属、同族」，好感度回答「我对这个人持何种态度」。两者独立：亲属可以疏远，陌生人也可以通过真实互助成为朋友。同营、同族、交易频繁不等于互相信任。

记忆保存事件证据；好感度聚合长期态度；激素是未来可选的增量调制。首期直接消费成功结算事实，不依赖记忆或激素系统先落地。记忆遗忘不回滚态度，态度不得充当罪行证据，也不得自动扩散为公众名声或子孙世仇。

产品验收关注：玩家能看懂方向与原因；普通交往不会快速刷出极端关系；新关系有机会进入有限圈子；关系不会压过救命时效、家庭保护线与既有婚育资格。

## 2. 核心规格与生命周期

| 项目 | 规则 |
|---|---|
| 容量 | 默认 36，配置范围 1～36；不随人口扩张。这里是模型预算，不主张 36 是现实社交能力的科学阈值 |
| 分值 | -7～+7 整数，共 **15 档（含 0）**；最终钳位 |
| 方向 | A→B 与 B→A 独立。一个事件只有明确规定双向时才生成两条影响 |
| 未存储 | 读为 0，含义是「中性／暂无记录」，不据此判断是否认识；0 值条目必须移除 |
| 自身与胎儿 | 禁止自指；胎儿不建表、不作为交往对象 |
| 确定性 | 不消费 RNG；稳定事件顺序、稳定驱逐、只读查询 |
| 时间 | 首期无自然衰减；所有限频用游戏时间，暂停与倍速不改变规则 |
| 持久化 | 态度与限频状态都随档保存；重新读取快照或存档不会再次计分 |
| 死亡 | 当拍死亡清理时移除指向亡者的条目及其限频记录；亡者自身表清空。悼念与历史归记忆／族谱，首期不新建亡者关系档案 |

极端关系不受永久锁定：正向帮助可以缓和敌意，伤害可以破坏友情，统一按事件规则更新。高好感不代表无条件救助，低好感不自动代表暴力或犯罪。

## 3. 等级与观察文案

下列为**观察者对对象的态度强度**，不保证双方关系对等，也不保证已有特定经历。UI 必须展示方向；尤其「生死之交」不可解释为双方已共同经历生死。

| 值 | 标签 | 解释 |
|---|---|---|
| +7 | 生死之交 | 极强信赖意愿，仍受能力与家庭安全约束 |
| +6 | 莫逆之交 | 深度信赖 |
| +5 | 挚友 | 强烈亲近 |
| +4 | 好友 | 明确亲近 |
| +3 | 友善 | 积极态度，普通往来可达到的上限 |
| +2 | 熟识 | 较积极的交往态度，不用于统计是否认识 |
| +1 | 有好感 | 轻微好意 |
| 0 | 中性 | 恩怨抵消或暂无记录 |
| -1 | 有嫌隙 | 轻微不快 |
| -2 | 冷淡 | 消极态度 |
| -3 | 芥蒂 | 明显不信任 |
| -4 | 怨怼 | 强烈不信任 |
| -5 | 仇隙 | 强烈敌意 |
| -6 | 宿敌 | 极强敌意，不自动传播给家人 |
| -7 | 不共戴天 | 敌意上限，仍可被后续事件缓和 |

标签从数值派生，不额外存一份等级状态；颜色之外同时显示符号、数字和文字。

## 4. 变化、驱逐与防刷

### 4.1 唯一事实与归因

只在真实结算成功后产生影响；任务计划、报价、路过、卸载重复快照、读档、普通自家卸货都不是人际贡献。每条事实须确定事实 ID、发生 tick、受体、对象、事件类型和是否亲历／目击。同一事实对同一有向人对只计一次；记忆与好感可以各消费一次，不能从记忆日志再次回灌好感。

同 tick 按固定结算阶段、事实序号、受体 ID、对象 ID、事件类型处理。采用逐事件钳位，不把相反事件先求和：到达上限后的帮助再遭伤害，与先遭伤害再被帮助可能不同，因此事件顺序是规则的一部分。

### 4.2 普通往来限频与强度上限

正常交易、未来有明确互动证据的共同劳动归为「普通往来」。同一受体→对象的所有普通往来共用冷却：默认 **24 游戏小时内至多 +1**；普通往来只会把分值提升到 +3，不会降低已有 +4～+7。负分可以逐步修复至 +3。

拆单、部分成交、多品类交易、更换中介不重置双方冷却；一笔订单与一个 episode 还必须各有完成事实去重。交易须为不同家户之间真实、非零且符合市场最小成交单位的履约。普通往来每个受体最多保留 36 个冷却对象；满额且均未过期时，新对象本次不计普通分，**交易仍然正常完成**。零分删除、关系驱逐不能清除未到期冷却，避免反复建表刷分。

重大帮助和伤害不受普通往来冷却，但必须有唯一事务和实质贡献；未来赠予不能靠拆分同一求助反复计分。没有可验证贡献或责任的候选事件保持禁用。

### 4.3 原子更新与容量驱逐

先验证事实、方向、限频与事件强度，再用旧值计算新值。归零即删除；数值未变时不刷新「最近变化」时间。新对象纳入**旧表加候选新条目**后，若超过有效容量，按 `绝对值升序 → 最近实际变化 tick 升序 → 对象 ID 升序` 删除首项，再一次性写回。新对象可以被立即淘汰。

不为血亲或配偶保留永久槽位。无衰减与最弱驱逐会使强关系圈较稳定，这是首期明确取舍；若长期样本中新增关系持续无法进入，应重新评估容量或替换机制，不暗中覆盖已有强关系。UI 的「最近变化」不称为「上次见面」。

## 5. 事件源与结构关系

| 来源 | 方向／幅度 | 结算与首期范围 |
|---|---|---|
| 成婚成功 | 双方各 +2 | **P0 唯一生产事件**：婚姻登记及家户转籍成功后一次；取消、失败、读档不计 |
| 正常交易履约 | 买卖委托人相互 +1 | 后置市场阶段；共用普通往来冷却与 +3 上限；不自动给售货员或全家加分 |
| 救急赠予到账 | 获助者→实际施助者 +2 | 后置；同一求助事务一次，真实缺口与到账贡献达标；普通家庭补给不算赠予 |
| 帮工完成／借物归还 | 实际受益者→履约者 +1 | 后置；普通往来规则。只有独立的重大救急贡献才可使用重大帮助事件 |
| 亲历盗窃或伤害 | 受害者→有证据的责任人 -3 | 后置，依赖真实损失和责任结算；不从负好感反推责任 |
| 第三方目击 | 目击者→责任人 -1 | 后置，必须有真实见证范围与证据；未实现见证机制前禁用 |
| 共同劳动 | 默认不计 | 同 POI 同时采收不证明合作；未来协作事务落地后按普通往来接入 |
| 拍卖失败／被拒求助／撤单／自然缺货 | 默认不计 | 正常竞争、资源不足、合法撤销不等于伤害；防止重复求助惩罚他人或贫困者自动积怨 |
| 死亡归咎 | 默认不计 | 仅未来有可归因伤害事实时接入，不因血亲自然死亡凭空迁怒 |

首期取消首次建条目的同族、配偶、血亲偏置，初始族人均为空表；已有结构关系继续由原系统消费。成婚只加本次 +2，不叠加「配偶直接 +6」，不向在世父母子女全体广播。否则被驱逐或归零后反复初始化可洗掉恩怨，血亲也会挤占整个圈子。亲子照料可在未来通过真实照料事件积累，不把新生儿预设为父母的知己。

## 6. 决策与市场边界

好感只在既有分支内部读取。先检查身份、能力、权限、预算、真实库存、可达性和求生时效，再比较普通成本，最后在合格候选中表达关系偏好，稳定 ID 最终破平。不得改写需求层级、路线、state、pending 或资源触发器，不新增世界扫描派任务。

首个行为切片采用当前求偶候选的有限破平：保留原资格与魅力优先级，在魅力相同的候选中，按发起者对候选的好感降序，再按原距离、ID 排序。不设正分准入门槛，不修改婚姻接受规则，不用初始空表阻断繁衍。具体接口见实施方案。

市场后置：好感属于具体委托人，不属于抽象家户，也不拿售货员的个人喜恶代替交易双方。撮合仍价格优先、时间优先；二者相同的可成交候选之间，用双方分值较小值降序破平，再按订单 ID。关系值在匹配时读取，不能挂单时预存一个与未知对手无关的信任布尔值。

首期只做撮合偏好，**不改价格、佣金，不设全局敌意拒单**。危机下关系偏好不能压过最快获得救命物资的方案；公共救助、亲属照料职责不由个人好感统一否决。未来自愿协作可由具体领域设计拒绝条件，但不能用「-4 拒绝一切协作」覆盖全部机制。救急赠予先保护施助家庭、验证权限与真实缺口，好感只影响选择，不把 +6 设为所有求助的共同门槛。

未来引入折扣需另行明确谁让利、授权下限、预算、佣金及封闭交易循环守恒；引入暴力、世仇须独立设计行为与证据门槛，极端数值本身不是授权。

## 7. 持久化与可观察性

态度、最近变化时间及普通往来冷却是行为状态，必须随档往返。读档验证范围、容量、重复对象、自指和时间合法性，不静默丢掉非法记录继续运行。旧档策略与 FABS 格式升级在实施时按实际兼容性处理；本次纯文档修订不升应用或存档版本。

快照依次覆盖 `snapshot.rs → world_snapshot.rs → snapshot_bin/encode.rs → snapshot-bin.js + rustworld.js`，二进制布局和工具解码器同步核对。等级由分值派生；若新增字典枚举则同步字典。详细实现只在根目录实施方案维护。

Inspector 展示「我→对方」，可同时显示「对方→我」但不混合成一条双向关系；按值降序、ID 升序列出条目。空表显示「暂无个人态度记录」，仍可显示亲属结构标签。点击跳转复用现有缓存交互；对象当拍已死亡或不存在时不给失效跳转。

「最近变化」只标记分数实际改变的时刻。若已有日志设施能接收记录，可显示原因与方向；首期不额外造无限历史日志。记录重大事件实际变化，或进入／离开绝对值 ≥6 区间，普通 +1 不刷屏。族谱不凭血缘自动涂成高好感，首期不建全图关系网络。

## 8. 阶段与验收

| 阶段 | 交付 | 关键验收 |
|---|---|---|
| P0 记录与观察 | 有界表、婚姻事件、存档、FABS、Inspector；行为开关关闭 | 重复结算不重复加分；保存恢复等价；剔除新增字段后的旧行为状态与基线相同 |
| P1 当前行为切片 | 求偶同魅力候选的好感破平，可独立开关 | 构造同魅力候选时关系改变选择；全零或开关关时恢复旧顺序；无新增婚育门槛 |
| P2 交易与协作 | 对应领域实际落地后接事件、限频及领域偏好 | 冷却跨拆单、驱逐、读档有效；普通交易不能越过 +3；资源与黄金守恒 |
| P3 深层关系 | 证据型伤害、重大互助，激素或世仇等独立扩展 | 多种子多代观察关系分布、圈子流动、存活与繁衍；不得用固定故事断言锁死演化 |

P0 不依赖内部市场、偷窃、记忆或激素；P1 只依赖 P0 和既有求偶。记录开启而行为关闭仍会增加存档、快照字节，因此不能要求新旧完整快照逐字节一致。确定性要求是**相同代码与配置**下同种子、不同步进批次和存读档续跑一致；旧行为投影另作对照。

## 9. 后续调优与红线

尚待实验的问题是：无衰减是否导致强关系长期封闭、24 小时冷却与 36 个冷却对象是否过严、重大帮助到达高分的速度、关系偏好对配偶与财富集中程度的影响。记录分值分布、饱和比例、新候选被驱逐率、冷却满额拒计率；调整需保留失败与灭绝样本。数值是待校准默认值，不作已验证平衡结论。

硬约束：有向且有界；无 RNG；所有变化经唯一结算；无首次建表重置偏置；关系不压过求生和家庭保护；冷却不因驱逐或读档重置；不自动扩散名声与仇恨；存档、快照与观察一致。后续激素调制须定义整数舍入、上限和限频交互后才能启用。
