> **状态**：方向设计，尚未实现、未排期。短中长期表示依赖顺序；工时为初步估算，不是交付承诺。

> **入口**：[文档导航](./README.md) · [长期路线图](./11-plan.md) · [空间与路网现状](./current/01-spatial-network.md) · [前端现状](./current/07-frontend-ui.md)。

## 1. 建议方向

将世界做成**有柔和光照、自然地表与聚落生活痕迹的斜俯视微缩景观**：远看能分辨草地、林地、坡地和村落，近看能观察族人在土路上往返、在泉边取水、在房屋间生活。

优先完成“地表质感 + 自然道路 + 信息减噪”的同一幅画面，再完善地貌与资源场景，最后按需要升级渲染技术。精美程度取决于色彩、形状、尺度和信息层级的统一；单独增加网格密度或换成 3D 引擎不能自动解决当前问题。

新增河流、山地等世界特征按[新地形特征与地理玩法规划](./22-plan-terrain-features.md)执行：该文负责生成、通行、选址与水资源语义，本文负责视觉实现。真实静态河流可作为中期切片，长期再扩展动态水文；不再将全部真实水系统一推迟到长期。

## 2. 当前画面诊断与实现依据

| 截图可见问题 | 已核对的实现依据 | 改进方向 |
|---|---|---|
| 大片绿、黄、灰渐变，像一块倾斜色板，坡地辨识弱 | `geo/terrain.rs` 使用全局倾斜加两组平滑谐波；已有高程与坡度，并非完全平面 | 先增强现有形体的明暗与材质分区，中期再丰富山脊、谷地和台地轮廓 |
| 地面偏暗、缺少细部，背景透出明显 | `math.js::computeElevationColor` 主要按归一化高程着色，叠加简化坡向明暗，透明度为 0.55；`main.js` 有同类兜底函数 | 使用稳定底色、统一光照和少量地表纹理，合并颜色规则，避免缓存与兜底表现漂移 |
| 地图边界笔直，悬在黑色背景中 | `render_world.js::drawTerrain` 逐格画四边形，随后画规则网格线 | 普通观察隐藏网格；用克制的地块侧壁、底部阴影和环境底色建立微缩沙盘感 |
| 黄、青、紫道路比地貌更抢眼 | `drawLanes` 高等级道路用高饱和色与微光，线宽恒定 | 普通观察用土、砂砾、石板材质；等级颜色留给道路分析视图 |
| 森林、水源和矿区主要像发光标记，缺少面积与体积 | `drawPois` 主要使用径向渐变、Emoji 和库存环 | 让 POI 成为小型景观群：树林、泉池、浆果灌丛、岩石露头 |
| 聚落中的门牌、拍卖牌和状态标记重叠 | `drawHouses` 在多类房屋上直接画文字；当前渲染顺序为地形 → POI → 房屋 → 道路 → 人物 | 引入标注避让和缩放分级；道路先于建筑绘制，再建立物体遮挡排序 |

截图显示秋季，但仍以大片绿色为主，季节的地表辨识度不足。截图中的道路彩色线属于现有等级表达，不能简单视为误开的调试模式。仅凭截图无法判断交互流畅度、完整种子或性能瓶颈。

关键实现入口：

- [地形生成与高程采样](../crates/sim_core/src/geo/terrain.rs)：当前 `sample_elevation` 取栅格值，不能把渲染平滑误认为物理采样已经平滑。
- [地形接收与颜色缓存](../frontend/js/rustworld.js)：重建顶点位置、梯度和颜色，地形主要在首次或重开时更新。
- [颜色计算](../frontend/js/math.js) / [颜色兜底与投影](../frontend/js/main.js)。
- [世界元素绘制](../frontend/js/render_world.js) / [帧循环](../frontend/js/render_canvas.js)。
- [存读档](../crates/sim_core/src/spatial/world_save.rs)：地形由种子重建，未来改变生成算法必须评估重建兼容性。

农田、哨塔和路卡的占地与通行均消费22及[融合设计 §6](./25-plan-system-integration.md#6-土地设施与通行)的内核事实；视觉样板不得提前画出不存在的生产、阻路或防御效果。S1～S3 仍可独立推进，不以农业、市场或记忆上线为前提。

## 3. 统一美术规则

### 3.1 色彩与材质

采用自然、偏暖、低至中饱和度的地面色，把明亮颜色留给选中对象和紧急事件。以下为首轮试色，不是固定产品配置。

| 表面 | 建议色彩 | 形状与细节 |
|---|---|---|
| 草地 | 苔绿 `#71845A`、浅草绿 `#91A56C` | 大片柔和过渡，少量细碎草斑 |
| 裸土与小路 | 土褐 `#927454` | 不规则边缘、轻微车辙或踩踏纹理 |
| 岩石 | 暖灰 `#8C8980` | 成组露头、统一受光面，避免均匀撒点 |
| 泉水 | 灰青蓝 `#557F87` | 浅色岸边、深色池心，少量高光 |
| 秋季植被 | 草黄、赭黄、暗橙 | 局部树冠先变色，保留常绿植物与裸土 |

光源采用固定世界方向，统一地形、树木、建筑的受光面与投影。近乎不透明的地面配合明暗控制，避免依靠透出黑色背景制造阴影。坡度负责裸岩倾向，局部低频纹理负责草土过渡；短期这些只是视觉材质，不宣称存在新的土壤或湿度模拟。

### 3.2 尺度、遮挡与信息

- 远景读地貌、聚落和主路；中景读资源区与房屋；近景读人物与生活细节。装饰密度随屏幕面积控制。
- 世界物体统一接地锚点与阴影尺度，逐步以同一套素材替换地图 Emoji；面板图标可继续使用现有体系。
- 普通观察仅突出选中、悬浮和关键异常；资源视图展示储量，道路视图展示等级，调试视图展示网格与节点。
- 保留全部信息的访问入口。拍卖房远景用小徽记或聚合数量，完整价格在悬浮、选中或拍卖面板中显示。
- 选中对象始终可辨认、可点击；树冠遮住人物时可局部淡化或画轮廓，命中检测使用与绘制一致的排序。

## 4. 短期：让现有地图先变好看

**范围**：1～2 个小迭代，粗估 5～10 人日，主要使用现有 Canvas 与快照；不新增地理行为规则。

S1～S3 可独立先行，但保留地表类别、岸线和连接设施的绘制接口；只能表现内核已经提供的地形事实，不先画横穿道路的装饰河。新地形查询与生成器的工作量另行估算。

### S1 · 地表、光照和边界

1. 统一地形着色入口，复用已有高程梯度计算法线，以环境光加方向光表现坡面；先保持现有顶点高度。
2. 草、土、岩以连续遮罩混合，加入低对比度纹理。纹理锁定世界坐标，缩放、旋转和刷新后不会重新随机撒点。
3. 普通视图关闭网格；边界增加地块侧面和柔和底影，强化有限沙盘定位。不要把矩形边界直接涂成海岸，以免暗示可航行水域。
4. 秋季先做植被和草色的有限过渡；更新季节材质时显式使颜色缓存失效，不能只改颜色函数而继续使用旧 `cell.color`。

### S2 · 道路与标注减噪

1. 保持真实贝塞尔路径、端点与移动位置，改为浅褐土路和灰褐石路；可增加受限的视觉宽度、路肩与断续纹理。
2. 绘制顺序调整为地表、贴地道路与阴影、场景物体、人物、交互覆盖层；复杂遮挡交由中期统一排序。
3. 等级颜色移入可切换分析层；等级 Tooltip 与现有耐久数值保持一致。
4. 按选中、悬浮、异常、普通信息排序分配标签空间；重要标签保留，普通房屋门牌在远景省略。

### S3 · 一个资源点和一座聚落的样板

先做一组树木、岩石、草丛及泉边素材，在现有 POI 周围生成景观群，再给房屋增加接地阴影与小块院地。道路和房屋占地内留白。纯装饰树不成为额外资源点，也不改变采收库存。

**交付物**：同一存档、镜头、缩放下的前后对照；普通/道路/资源视图；至少一个近景泉边与林地样板；静态缓存与性能记录。

**退出标准**：默认画面能先认出地貌和聚落；选中对象不被标牌覆盖；道路、房屋和人物位置一致；换世界不残留装饰；性能符合第 8 节预算后再扩大素材覆盖。

## 5. 中期：建立有辨识度的地貌与资源景观

**范围**：短期样板通过后推进。原有视觉样板与素材工作粗估 3～6 周；新增地形规划 T0～T3 的内核、导航和水资源工作不包含在此估算内，完成基础原型后单独排期。

### M1 · 宏观地貌先于细碎噪声

生成顺序以[地形专项方案 §4](./22-plan-terrain-features.md#4-生成顺序与有效世界保障)为准：内核先完成高程、水系、通行与选址约束，再生成合法路网并通过校验，最后添加材质与装饰。首批 T1 做丘陵台地、山脊和山口；T2 做两岸河谷；湖畔盆地等 T3 组合按需增加。

- 用少量可控的山脊、洼地和台地塑造轮廓，保留足够的平缓建房区与可达资源。
- 多尺度噪声用于打散规则感，不能用增加噪声替代有目的的空间结构。
- 视觉细分可以提高表面细腻程度；涉及高度变化时，必须同时核对物理采样、路网曲线、POI 和房屋的接地位置。
- 改进采样前验证当前栅格边界、插值与坐标约定；不能只替换为平滑采样就假定所有存量路径仍贴地。

### M2 · 资源区成为地景

| 区域 | 场景表达 | 与模拟的边界 |
|---|---|---|
| 清泉与河湖岸点 | 小泉池、湿润土色、岸石、芦草 | S3 仍用原水源 POI；T2/T3 按专项方案共享水资源池，装饰不得挡住真实岸边取水位置 |
| 森林 | 主树群、林缘灌木、林下暗部 | 资源减少优先改变可采部分、树桩或冠层状态，不让整片树林随库存抖动消失 |
| 果丛 | 不规则灌木簇、果实点缀 | 果实丰度对应库存，采收地点可辨认 |
| 石矿与金矿 | 岩脊露头、碎石、局部矿脉 | 金色只作小面积点缀，不能让整座山发光 |
| 聚落 | 院地、门前路、少量生活摆设 | 房屋与通行区域优先，装饰不能制造并不存在的仓储或生产设施 |

### M3 · 季节、素材和渲染组织

- 建立统一视角、接地点、色板和光向的树、石、房屋素材集；尺寸变体使用可复现的对象哈希选择。
- 春季嫩色、夏季深绿、秋季枯草与变色树冠、冬季局部覆雪。只消费已存在的季节/气温事实；雨、洪水等新事件在有模拟来源前不展示为事实。
- 按相机深度排序树、房屋、人物，使用稳定 ID 打破同深度并列。高树跨越大范围时考虑分层精灵或局部遮挡，不能只靠屏幕 y 排序处理所有坡地情况。
- 地形和装饰分块缓存，远景减小树木数量、纹理密度和标签数量；相机持续旋转期间也要测性能。
- 将地形、装饰、场景物体、标注逐步拆为职责清晰的绘制模块，遵守单文件行数规则。

### M4 · 两岸河谷完整切片

对接[地形专项方案 T2](./22-plan-terrain-features.md#6-分阶段落地与景观计划对接)，制作静态主河、浅滩、河滩与河阶。首期采用内核认可的固定浅滩连接，不依赖桥梁施工或完整水文模拟。

- 水域、岸线、浅滩位置与水面高程来自内核；前端只增加高光、岸石和植被。
- 河床先绘制，水面与岸边物体按遮挡关系组织；人物在浅滩的脚部可以局部被水覆盖，不能把整条路画在水面上冒充桥梁。
- 将未来桥面作为独立高程的连接设施预留，不把桥当作道路纹理；T2 不生成桥梁对象。
- 湖泊、湿地、峡谷与瀑布待各自 T3 内核契约通过后逐项加入，避免纯视觉先行造成错误地理暗示。

**真实水系的准入门槛**：流向与出口、静态水域、合法跨水连接、共享取水语义、建房禁区及连通性/生存诊断一同通过。未完成前不增加横穿现有道路的大河、深湖或不可达悬崖，避免人物“穿水”“穿山”。

**交付物**：T1 山口与台地样板、T2 两岸河谷切片、四季同镜头对照、资源场景素材集、遮挡与标签系统、多种子可达性和生存诊断；T3 湖畔盆地作为后续扩展。

## 6. 长期：让景观记住社会的历史

**范围**：中期验证后按专题推进，约 2～6 个月以上；依赖玩法范围、美术产能与性能结果，不宜一次承诺全部内容。

### L1 · 地形与生态形成真实因果

在中期静态地形与水系基础上，按专项方案 T4 逐步评估枯丰水期、洪水、桥梁工程、土壤/湿度和植被变化。坡地影响道路，平缓地带吸引聚落，水源影响生活和农业。动态通行恢复与存档契约须先完成，具体规则由内核计算，前端只呈现事实。

与[农业规划](./17-plan-farmland-agriculture.md)共享地块和土地用途定义，避免农业、植被和水系各自维护一套互不一致的地表。

### L2 · 景观记录时间

道路变宽或荒废、聚落扩展、林地采伐与恢复、废宅遗址，逐渐形成可辨认的年代感。与[人物日常生活规划](./20-plan-everyday-life.md)连接门前活动、取水点、公共空地，让生活成为景观的一部分。

凡是影响回放的土地变化，明确采用入档状态、确定性事件或可验证重建方案。前端不能凭当前人口猜测过去的森林覆盖，也不能在回滚后保留未来的废墟。

### L3 · 按测量结果升级渲染

继续以 Rust/WASM 作为唯一模拟内核，评估独立的 GPU 渲染层，逐步替换绘制实现。启动条件是：缓存与缩放分级后仍持续超出性能预算，或真实遮挡、水面和大规模植被效果无法在现有方案中合理实现。

先做“一个地形块 + 一片树群 + 一座房屋 + 一名可选中人物”的原型，对比现有 Canvas 的帧耗时、内存、资源加载、镜头与命中行为，再决定技术栈。WebGL/WebGPU 的选择留给届时的平台兼容性与原型数据，不在规划阶段绑定引擎。

**长期退出标准**：景观变化能够解释资源、迁徙或聚落历史；同一存档回放得到一致的世界事实；升级后的渲染层保留低画质降级和原有观察交互。

## 7. 数据与工程约束

| 数据类别 | 权威来源与更新方式 | 约束 |
|---|---|---|
| 高程、坡度、真实地表状态 | Rust 生成或更新，经现有 FABS 链路传递 | 不由前端另造物理地形；静态数据按需传输 |
| 河湖几何、水位、岸带、浅滩与后续桥梁 | 新地形方案的内核地理与连接对象 | 水面高程独立于河床；禁行、可建与交互点共用内核事实，装饰不得反向决定规则 |
| 道路、房屋、资源储量 | 现有世界快照 | 材质映射不得改变真实坐标、路线、容量与消耗 |
| 草斑、装饰石、素材变体 | 世界坐标、稳定对象 ID 与视觉种子派生 | 不消费共享模拟 RNG，不随帧率变化；没有视觉种子字段时需设计传递或固定哈希方案 |
| 季节颜色、水面微动 | 已有世界时间/气候事实 + 纯视觉函数 | 截图验收固定视觉时刻；暂停与回放时不漂移 |
| 缓存和缩放细节层级 | 前端派生，可随时重建 | 不写入模拟状态；换世界、载入、地形变化时失效 |

缓存键应包含世界实例代次、地形内容版本、素材/风格版本、季节档位；屏幕空间缓存还要包含相机、画布尺寸与 DPR。前端实例代次仅管理缓存，不写进确定性快照；不得改用 FABS 字符串表 epoch 判断跨世界。内存设上限并释放旧缓存，不能无限保存每种镜头结果。

生成算法变动会影响仅按种子重建的地形。未来须明确应用版本拒绝旧档，或增加生成器版本/保存必要地形数据；不能把旧路网和新地貌静默组合。新增持久化字段时再评估存档结构版本，不能把每次材质改色都变成格式升级。

实现时按根 [AGENTS.md](../AGENTS.md) 及相关局部指南执行：固定 Tick、Agent 自主决策、集中配置、快照四处同步与 WASM 双副本保持不变。快照 JSON 真值赋值的当前文件为 `world_snapshot.rs`，连同 `snapshot.rs`、二进制编码、解码和前端映射一起核对。纯视觉参数集中在前端渲染配置，影响模拟的参数走 `SimConfig` 全链路。

## 8. 验收与性能预算

### 8.1 视觉与交互

以固定种子、配置、Tick、相机、窗口尺寸、DPR 和视觉时刻保存前后对照。截图中的局面需要对应存档才能严格复现，不能从图片反推出种子；没有该存档时建立新的固定基线。

- 覆盖远/中/近三档镜头、四季，以及初始聚落和高密度聚落。
- 普通视图下，评审者能在约 5 秒内指出主要聚落、水源区和主路；记录识别错误，作为设计迭代依据。
- 选中/悬浮标签不互相遮盖；拥挤时普通标签聚合或省略，不能遮住当前目标。
- 缩放、旋转、镜头跟随、读档、重置、时光回溯后，无纹理漂移、旧世界残留、物体悬空或点击错位。
- 资源断流有可辨认反馈；漂亮水面或树林不能掩盖“当前不可采”的事实。
- 新地形验收同步覆盖山口、浅滩与河阶；湖泊等扩展上线后补充对应场景。区分“水面仍存在”和“可采额度耗尽”，按专项方案的资源语义展示。

### 8.2 测量方式与建议预算

以下为待验证的工程目标，不是现有实测成绩。先记录测试机器、浏览器、分辨率、DPR、人口与倍速；固定镜头和连续拖动/跟随镜头分别测量，预热后各采样至少 60 秒。

| 指标 | 首轮目标 | 超标处理 |
|---|---|---|
| 主线程渲染与 UI 耗时 | 参考桌面设备 p95 ≤ 16 ms，争取接近 60 FPS | 先减标签、纹理层和装饰数量，低画质以稳定 30 FPS 为目标 |
| 新增地表/装饰绘制耗时 | 同条件 p95 增量 ≤ 3 ms | 调整分块、缓存、可见性剔除和缩放分级 |
| 纯美术改动的仿真吞吐 | 同设备同负载下降不超过约 5%，重复确认测量噪声 | 核查主线程争用与快照处理，不能减少模拟 Tick 掩盖回退 |
| 新增视觉缓存内存 | 初始上限建议 64 MiB | 缩小图块、限制 DPR/缓存档数、淘汰不可见块 |
| 重置/读档与相机变动 | 单独记录首帧及缓存重建 p95，与基线对照 | 分批重建装饰，避免在交互帧集中生成全部素材 |

重复图元预渲染、静态与动态层分离可作为缓存方案的技术依据；实际收益仍需在本项目的相机运动和地形投影下验证。参见 [MDN：Canvas 性能优化](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas)。

### 8.3 实施门禁

- 本文仅提出规划；本次文档交付运行文档维护体检和差异检查。
- 后续前端实现运行 `frontend-check.js`，按[浏览器指南](./03-browser-guide.md)做视觉与交互验收；使用[性能指南](./15-profiling-and-benchmarking-guide.md)建立基线。
- 涉及 Rust/版本常量变更时重编译并同步 WASM 双副本，执行 `cargo test --lib`、`test-wasm.js` 与适用的确定性门禁。
- 涉及快照字段执行 `test-snapshot-bin.js`；配置变更执行 `config-check.js`；地形行为变化增加多种子、存读档和回溯诊断。行为有意变化时不能要求新旧生成算法结果相同，但同版本同种子必须确定性一致。
- 不提交临时单元测试；各阶段实现完成后再同步现状文档、版本和 changelog，不能把本文的规划写成已实现机制。

## 9. 首个可实施切片

建议第一批只交付：**自然草土地表、统一坡面光照、土石道路、普通视图标签减噪、一处泉边和林地样板**。先在高密度聚落场景证明“更精美且更容易看懂”，再决定是否扩展地貌生成与完整素材库。

优先级：S1 + S2 → S3；新地形 T0 查询契约通过后 → M1/T1 山口台地 → M4/T2 两岸河谷 → 按需 T3 地貌扩展 → L1/L2/T4 动态地理与景观历史。M2/M3 随各切片提供素材与遮挡支持；GPU 渲染升级始终按性能证据启动，不作为增加河流和山地的前置条件。
