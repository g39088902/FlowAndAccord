## 1. 建议方向

将世界做成**有柔和光照、自然地表与聚落生活痕迹的斜俯视微缩景观**：远看能分辨草地、林地、坡地和村落，近看能观察族人在土路上往返、在泉边取水、在房屋间生活。

优先完成“地表质感 + 自然道路 + 信息减噪”的同一幅画面，再完善地貌与资源场景，最后按需要升级渲染技术。精美程度取决于色彩、形状、尺度和信息层级的统一；单独增加网格密度或换成 3D 引擎不能自动解决当前问题。

新增河流、山地等世界特征按[地图模板总纲](./22-plan-terrain-features.md)执行：该文以地图模板为核心，负责模板清单、生成、通行、选址与水资源语义，本文负责视觉实现。真实静态河流已作为中期切片落地（T2，v1.47.5）；长期再扩展动态水文（T4）。

## 3. 统一美术规则

### 3.1 色彩与材质

采用自然、偏暖、低至中饱和度的地面色，把明亮颜色留给选中对象和紧急事件。下表“当前色值”是**已落地实现**（`frontend/js/math.js` 与 `frontend/js/render_world.js`），不是待确认的试色。

| 表面 | 当前色值 | 形状与细节 |
|---|---|---|
| 草地 | 由归一化高程插值出苔绿→浅草绿（基准约 `rgb(108,138,88)` → `rgb(156,156,114)`），`naturalFertility` 再提绿（G +10~14，R/B 略降） | 连续过渡；**草斑/细碎纹理未做** |
| 裸土与小路 | 坡度 12°→28° 用 smoothstep 过渡到土色 `rgb(152,138,114)` | 道路五级自然色阶（泥径/夯土/石道/石板/通衢），见 S2 |
| 岩石 | 坡度 >28° 再 smoothstep 过渡到暖灰（`rgb(130~145, 126~140, 118~134)`，随高程提亮） | 成组露头未做；当前是连续坡度派生，不撒点 |
| 泉水 | `ShallowWater rgb(62,152,176)`、`DeepWater rgb(36,104,138)`、`RiverBank rgb(168,152,126)` | 三层水光 + 岸带 + 浅滩踏石，见 S2.1 |
| 秋季植被 | ⏳ 未实现（着色函数不读季节） | 局部树冠变色、保留常绿与裸土 |

光源为固定世界方向（左上方俯视 `L = normalize(-0.45, -0.60, 0.66)`），光照强度 `clamp((0.54 + 0.46·diffuse)·ao, 0.52, 1.22)`，AO 随坡度衰减（`max(0.70, 1 − slope/65·0.30)`）；地形、房屋体块、族人投影共用同一受光约定。地面为**不透明填充**，不再依靠透出深色背景制造阴影。坡度负责草/土/岩倾向，`naturalFertility` 负责绿度；这些只是视觉材质，不宣称存在新的土壤或湿度模拟。

### 3.2 尺度、遮挡与信息

- 远景读地貌、聚落和主路；中景读资源区与房屋；近景读人物与生活细节。装饰密度随屏幕面积控制。⏳ 分级 LOD 与分块缓存未做。
- ✅ 世界物体统一接地锚点与阴影尺度：房屋为 2.5D 微缩体块 + 落底阴影，POI 为贴地底座 + 标记，族人带微接触投影。
- ✅ 立体实体统一按相机深度远 → 近绘制（`drawWorldEntities()`）；新增世界实体必须登记进同一队列，严禁在 `render()` 里另开整层绘制。
- ✅ 普通观察只突出选中、悬浮和关键异常：库存环仅在 `zoom ≥ 0.70` 或选中时显示；网格默认关闭（`G` 键切换），道路等级色阶仅在 `R` 键热力图模式展示。
- ◐ 保留全部信息的访问入口：拍卖房远景仍显示 `🔨` 标牌，完整价格在悬浮/选中/拍卖面板中查看。⏳ 标签避让与聚合未做。
- ◐ 选中对象始终可辨认、可点击：拾取逻辑仍按 `sim.*` 原序遍历，与绘制队列解耦；树冠遮人时的局部淡化/轮廓未做（尚无树冠素材）。

## 4. 短期：让现有地图先变好看

**范围**：1～2 个小迭代，粗估 5～10 人日，主要使用现有 Canvas 与快照；不新增地理行为规则。

S1～S3 可独立先行，但保留地表类别、岸线和连接设施的绘制接口；只能表现内核已经提供的地形事实，不先画横穿道路的装饰河。

### S1 · 地表、光照和边界

1. ✅ **统一地形着色入口**：`math.js::computeElevationColor` 是唯一实现，复用已有高程梯度算法线，环境光 + 方向光表现坡面；`main.js::getElevationColor` 改为委托 + 纯色兜底；`rustworld.js` 在快照重建时一次算好 `cell.color` 缓存。
2. ◐ **草、土、岩连续混合**：已按坡度 12°/28°/45° 与肥力做 smoothstep 连续遮罩（消除离散台阶）；⏳ **低对比度纹理未做**——当前仍是逐格纯色填充，尚未引入锁定世界坐标的草斑/土纹，缩放旋转刷新后重随机的问题因此也还不存在。
3. ✅ **普通视图关闭网格 + 边界沙盘化**：`sim.showGrid` 默认 `false`（`G` 键切换）；四向侧壁（`#5A5043` / `#50463B` / `#38322B` / `#3D362E`）与底部 `rgba(0,0,0,0.26)` 投影强化有限沙盘定位，未把矩形边界涂成海岸。
4. ⏳ **季节材质过渡未做**：需要先加季节因子，再显式使 `cell.color` 缓存失效——只改颜色函数而继续用旧缓存会毫无效果（`rustworld.js` 的 `_terrainCached` 是单标志）。

### S2 / P0 · 道路与建筑层级反转 + 道路色调柔和化 ✅ 已落地

1. **渲染层级反转**：`render_canvas.js::render()` 现行顺序为 `drawTerrain()` → `drawLanes()` → 贴地图元（营地辖区连线 + POI 底座）→ `drawWorldEntities()`（POI 标记 + 房屋 + 族人）→ 登基礼花。道路作为地表踩踏纹理先画，房屋带落底投影压在道路之上。
2. **自然泥土与石道路谱（默认观察模式）**：默认视角关闭高饱和亮黄/亮橙与外发光（`rgba(245,158,11,0.25)` 仅保留在热力图模式）；线宽随踩踏度 `1.2px → 2.8px` 递增，色阶为：
   - 1 级（wear 0.3~1.0）：踩踏泥径 `rgba(142,115,84,≤0.55)` + 虚线；
   - 2 级（wear 1.0~2.0）：夯土小路 `rgba(122,98,72,≤0.75)`；
   - 3 级（wear 2.0~3.0）：平整石道 `rgba(108,95,80,0.85)`；
   - 4 级（wear 3.0~4.0）：精修石板 `rgba(132,128,120,0.90)`；
   - 5 级（wear ≥ 4.0）：帝国通衢 `rgba(158,154,144,0.95)`。
3. **分析功能完整保留**：`R` 键热力图模式保留明艳色阶（`rgba(180,83,9)` → `#f59e0b` → `#facc15` → `#38bdf8` → `#d946ef`）与高等级外发光；悬浮 Tooltip 数据两条路径完全一致。

### S2.1 / P1 · 河流清澈水系化与波光分层 ✅ 已落地（T2 内核 + 前端渲染）

1. **水体网格材质通透化**：`computeElevationColor` 中 `ShallowWater` / `DeepWater` / `RiverBank` 已改为清透碧蓝与浅金砂岸，仍保留法线光照与 AO，河谷凹槽自然有深浅层次。
2. **三层立体水系折线渲染**：`render_world.js::drawTerrainFeatures` 对 `feature.kind === 'River'` 分三层落笔——深底水层 `rgba(32,86,122,0.45)`、主流水层 `rgba(56,158,202,0.82)`、波光反射层 `rgba(235,248,255,0.65)` 断续高光。
3. **生动水岸与浅滩踏石**：`RiverBank` 为 `rgba(188,160,120,0.48)` 浅金砂漫滩；`ShallowFord` 为 `rgba(215,196,142,0.90)` 卵石踏道 + `rgba(255,255,255,0.65)` 浪花高光斑；`SpringValley` 为柔和土褐细带。

> 水面高程、岸线、浅滩位置全部来自内核 `TerrainFeature`；`Ridge`/`Saddle`/`Terrace` 三类山脊/山口/台地轮廓随特征删除（v1.47.7），前端不再绘制。

### S2.2 / P2 · 世界实体统一相机深度绘制 ✅ 已落地（v1.47.8 → v1.47.9）

- `drawWorldEntities()` 每帧把 POI 标记、私产宅舍、部落民收进同一队列，按 `project3D().depth`（`ry·sinX + z·cosX`，数值越大越靠近视点）**升序**绘制；同深度保持快照原序（`Array.sort` 稳定）以维持渲染确定性。
- 每帧重算，相机旋转后不残留旧序；排序只作用于绘制队列，`sim.pois` / `sim.houses` / `sim.agents` 顺序与点击拾取、Inspector 遍历逻辑不变。
- 贴地图元（POI 底座、营地暖光、辖区连线）留在更早的地面 pass，避免暖光糊在近处建筑上。

### S3 · 一个资源点和一座聚落的样板 ⏳ 未实施

先做一组树木、岩石、草丛及泉边素材，在现有 POI 周围生成景观群，再给房屋增加接地阴影与小块院地。道路和房屋占地内留白。纯装饰树不成为额外资源点，也不改变采收库存。

当前基线：POI 仍是「贴地阴影 + 色圆底座 + Emoji 图标」，没有景观群；房屋已有落底阴影但无院地。素材必须走**世界坐标 + 稳定对象 ID/视觉种子哈希**，不消费共享模拟 RNG；没有视觉种子字段时需先设计传递方案。

**交付物**：同一存档、镜头、缩放下的前后对照；普通/道路/资源视图；至少一个近景泉边与林地样板；静态缓存与性能记录。

**退出标准**：默认画面能先认出地貌和聚落；选中对象不被标牌覆盖；道路、房屋和人物位置一致；换世界不残留装饰；性能符合第 8 节预算后再扩大素材覆盖。

## 5. 中期：建立有辨识度的地貌与资源景观

**范围**：短期样板通过后推进。素材与遮挡工作粗估 3～6 周；T3 内核（湖泊/湿地/峡谷/瀑布）另行排期。

### M1 · 宏观地貌先于细碎噪声 ◐ 内核主体已落地

生成顺序以[地形专项方案 §8](./22-plan-terrain-features.md#8-生成顺序与有效世界保障)为准：内核先完成高程、水系、通行与选址约束，再生成合法路网并通过校验，最后添加材质与装饰。

- ✅ T1 山口聚落（`mountain_pass_v1`：主脊 + 山口鞍部连续起伏，v1.47.7 起不含台地）与 T2 两岸河谷（`river_valley_v1`：蜿蜒主河 + 河阶 + 两岸浅滩）均已落地；`terrainProfile: 'random'` 按种子哈希在两者间 ~50% 轮换，创世后把实际模板名回写入档。
- ✅ 用少量可控的山脊、洼地塑造轮廓，保留平缓建房区与可达资源；地形感知路网（`terrain_network.rs`）保证路线绕山、经浅滩跨河，而非直线穿水。
- ◐ 多尺度噪声用于打散规则感：目前是倾斜大势 + 平滑谐波 + 模板骨架，**多尺度噪声与支脊未实现**。
- ⏳ 视觉细分提高表面细腻程度：`sample_elevation` 仍为最近邻；若改变采样方式，必须同时核对物理采样、路网曲线、POI 和房屋接地位置。
- ⏳ **D-A 装饰系统**（v1.48.0）：在 T1/T2 骨架之上叠加 Accent 装饰层（Tree/Boulder/Bush/RockCluster/GrassTuft），使用独立 `accent_rng` 生成。
- ⏳ **D-B 子特征注入**（v1.48.0）：按 seed 哈希概率在 T1 注入山脚湖/瀑布/密林，在 T2 注入牛轭湖/峭壁/河岸林带。

> ❌ **不再规划独立 T3 profile**（v1.48.0 决策）：湖泊/峡谷/瀑布通过子特征注入实现；湿地因视觉辨识度低明确删除。

### M3 · 季节、素材和渲染组织 ◐ 深度排序已落地，素材与季节未做

- ⏳ 统一视角、接地点、色板和光向的树、石、房屋素材集；尺寸变体使用可复现的对象哈希选择。
- ⏳ 春季嫩色、夏季深绿、秋季枯草与变色树冠、冬季局部覆雪。只消费已存在的季节/气温事实（`snap.season`、`season_progress`）；雨、洪水等新事件在有模拟来源前不展示为事实。改季节材质必须让 `cell.color` 缓存失效。
- **与光照方案的分工**：地表**反照率**（本节）与**光**（[动态季节光照方案](./27-plan-seasonal-lighting.md)：光向/强度/色温/阴影/天空氛围）分开维护，但共用同一季节相位与同一 `cell.color` 失效机制，禁止各自维护一套季节时钟。光照方案落地后可先消费其 `SimLighting.phase()`，本节的季节调色再接入。
- ✅ 按相机深度排序 POI、房屋、人物，使用稳定快照原序打破同深度并列（v1.47.9）。⏳ 高树跨越大范围时的分层精灵/局部遮挡待有树冠素材后再评估。
- ⏳ 地形和装饰分块缓存、远景减量与相机旋转期间的性能测量。
- ◐ 绘制模块职责：`drawTerrain` / `drawTerrainFeatures` 已独立成函数但仍内嵌于 `render_world.js`（现约 770 行，逼近 800 行上限）；新增景观素材前应先拆分 `render_terrain.js` / `render_features.js`。

### M4 · 两岸河谷完整切片 ◐ 内核与基础渲染已落地，子特征待注入

对接[地形专项方案 T2](./22-plan-terrain-features.md#19-分阶段落地与景观计划对接)，静态主河、浅滩、河滩与河阶已落地（v1.47.5）。

- ✅ 水域、岸线、浅滩位置来自内核；前端只增加高光、岸石和植被（岸石/植被待 D-A/M2 素材）。
- ✅ 河床先绘制，水面与岸边物体按遮挡关系组织；人物在浅滩沿内核实际路线过水并按 `terrain_shallow_water_cost` 减速。
- ⏳ 未来桥面作为独立高程的连接设施预留，不把桥当作道路纹理；T2 不生成桥梁对象。
- ⏳ **D-B 子特征注入**（v1.48.0）：湖泊（牛轭湖）、峡谷（河谷峭壁）、瀑布（山涧飞瀑）通过子特征注入器实现，不再新增独立 profile。

**真实水系的准入门槛**：流向与出口、静态水域、合法跨水连接、共享取水语义、建房禁区及连通性/生存诊断一同通过。T2 已满足上述门槛；未完成的子特征不得提前画成可涉水或可通行的视觉暗示。

**交付物**：✅ T2 两岸河谷切片与全图连通性校验（`validate_terrain_world`）；⏳ T1 山口景观素材样板、四季同镜头对照、资源场景素材集、遮挡与标签系统、生态落位的生存距离诊断（`ecology/spawn.rs` 尚未消费地表查询）；D-B 子特征注入作为后续扩展。

## 6. 长期：让景观记住社会的历史

**范围**：中期验证后按专题推进，约 2～6 个月以上；依赖玩法范围、美术产能与性能结果，不宜一次承诺全部内容。

### L1 · 地形与生态形成真实因果

在中期静态地形与水系基础上，按专项方案 T4 逐步评估枯丰水期、洪水、桥梁工程、土壤/湿度和植被变化。坡地影响道路，平缓地带吸引聚落，水源影响生活和农业。动态通行恢复与存档契约须先完成，具体规则由内核计算，前端只呈现事实。

与[农业规划](./17-plan-farmland-agriculture.md)共享地块和土地用途定义（`LandUseKind` 已预留 `Farm`/`Defense`），避免农业、植被和水系各自维护一套互不一致的地表。

### L2 · 景观记录时间

道路变宽或荒废、聚落扩展、林地采伐与恢复、废宅遗址，逐渐形成可辨认的年代感。与[人物日常生活规划](./20-plan-everyday-life.md)连接门前活动、取水点、公共空地，让生活成为景观的一部分。

凡是影响回放的土地变化，明确采用入档状态、确定性事件或可验证重建方案。前端不能凭当前人口猜测过去的森林覆盖，也不能在回滚后保留未来的废墟。

### L3 · 按测量结果升级渲染

继续以 Rust/WASM 作为唯一模拟内核，评估独立的 GPU 渲染层，逐步替换绘制实现。启动条件是：缓存与缩放分级后仍持续超出性能预算，或真实遮挡、水面和大规模植被效果无法在现有方案中合理实现。

先做“一个地形块 + 一片树群 + 一座房屋 + 一名可选中人物”的原型，对比现有 Canvas 的帧耗时、内存、资源加载、镜头与命中行为，再决定技术栈。WebGL/WebGPU 的选择留给届时的平台兼容性与原型数据，不在规划阶段绑定引擎。

**长期退出标准**：景观变化能够解释资源、迁徙或聚落历史；同一存档回放得到一致的世界事实；升级后的渲染层保留低画质降级和原有观察交互。

## 7. 数据与工程约束

| 数据类别 | 权威来源与更新方式 | 约束 |
|---|---|---|
| 高程、坡度、地表类别、真实地表状态 | ✅ Rust T0/T1/T2 生成或更新，经 FABS 地形 section 传递 | 不由前端另造物理地形；静态数据只在 `terrain_dirty` 帧下发 |
| 河湖几何、水位、岸带、浅滩与后续桥梁 | ✅ 内核 `TerrainFeature` / `WaterPool` / `TerrainConnection`；桥梁待 T4 | 水面高程独立于河床；禁行、可建与交互点共用内核事实，装饰不得反向决定规则 |
| 道路、房屋、资源储量 | 现有世界快照 | 材质映射不得改变真实坐标、路线、容量与消耗 |
| 草斑、装饰石、素材变体 | ⏳ D-A：`accent_rng` 生成 + 世界坐标锁定（id u32 + pos Vec3 + scale + rotation + tint） | 独立 `accent_rng` (`seed ^ 0x4143_4345_4E54_3031`)，不消费共享模拟 RNG；FABS Section 21 持久化 |
| 季节颜色、水面微动 | ◐ 季节/气温事实已随快照下发（`season`、`season_progress`、`temperature`），视觉映射未做 | 截图验收固定视觉时刻；暂停与回放时不漂移；改色须让 `cell.color` 缓存失效 |
| 缓存和缩放细节层级 | 前端派生，可随时重建 | 不写入模拟状态；换世界、载入、地形变化时失效 |

当前缓存事实：`rustworld.js` 以单个 `_terrainCached` 同时管理网格与地貌特征，并在 READY / LOAD_RESULT / REWIND_RESULT / RESET_DONE 时清除；跨世界字符串表缓存以 `STR_TAB.start_index == 0` 为唯一判据（**不得**改用 FABS epoch，见根 AGENTS.md §4.5.1）。引入装饰缓存后，缓存键需包含世界实例代次、地形内容版本（`terrain_generator_version` + `terrain_profile`）、素材/风格版本、季节档位；屏幕空间缓存还要含相机、画布尺寸与 DPR。内存设上限并释放旧缓存，不能无限保存每种镜头结果。

生成算法变动已由版本门禁覆盖：`terrain_generator_version`（当前 3）+ `terrain_profile` 与 `SAVE_FORMAT_VERSION`（当前 7）共同拒绝旧档，地形与水池直接从存档恢复，不存在“旧路网 + 新地貌”静默拼接。后续若新增持久化字段，再评估存档结构版本，不能把每次材质改色都变成格式升级。

实现时按根 [AGENTS.md](../AGENTS.md) 及相关局部指南执行：固定 Tick、Agent 自主决策、集中配置、快照四处同步与 WASM 双副本保持不变。快照真值赋值文件为 `crates/sim_core/src/spatial/world_snapshot.rs`，连同 `snapshot.rs`、`snapshot_bin/encode.rs`、`snapshot-bin.js`、`rustworld.js` 一起核对。纯视觉参数集中在前端渲染配置，影响模拟的参数走 `SimConfig` 全链路（当前 237 字段）。

## 8. 验收与性能预算

### 8.1 视觉与交互

以固定种子、配置、Tick、相机、窗口尺寸、DPR 和视觉时刻保存前后对照。截图中的局面需要对应存档才能严格复现，不能从图片反推出种子；没有该存档时建立新的固定基线。

**已通过**（v1.47.5 / v1.47.8 / v1.47.9 实测）：

- ✅ 道路不再切过屋顶；道路、房屋与人物位置一致，跨图层遮挡按相机深度正确（统一队列深度序 0 违规）。
- ✅ T2 水面、岸线、浅滩、人物与道路投影一致；普通陆路不穿深水，仅经浅滩跨河；HUD 水源储量按水池去重。
- ✅ 读档/重置/回溯后无旧世界特征残留与字符串串味（`test-snapshot-bin.js` 换世界场景 + `test-determinism.js` 存读档/回溯套件）。

**待验收**：

- ⏳ 覆盖远/中/近三档镜头、四季，以及初始聚落和高密度聚落（四季地表尚无差异，验收需等 S1-4/M3）。
- ⏳ 普通视图下，评审者能在约 5 秒内指出主要聚落、水源区和主路；记录识别错误，作为设计迭代依据。
- ⏳ 选中/悬浮标签不互相遮盖；拥挤时普通标签聚合或省略（当前只有缩放分级）。
- ⏳ 缩放、旋转、镜头跟随、读档、重置、时光回溯后，无纹理漂移、旧世界残留、物体悬空或点击错位（纹理尚未引入，该项在 S3 后复验）。
- ◐ 资源断流有可辨认反馈；漂亮水面或树林不能掩盖"当前不可采"的事实（水面已与库存解耦，树林素材上线后需复验）。

- ⏳ D-B 子特征注入后：补充山口、浅滩、河阶之外的湖泊/峭壁场景（v1.48.0 取消湿地、取消独立 profile）。

### 8.2 测量方式与建议预算

**以下仍为待验证的工程目标，至今没有实测成绩**（第 8.1 节的验收均为功能正确性，不含帧耗时基线）。先记录测试机器、浏览器、分辨率、DPR、人口与倍速；固定镜头和连续拖动/跟随镜头分别测量，预热后各采样至少 60 秒。

| 指标 | 首轮目标 | 超标处理 |
|---|---|---|
| 主线程渲染与 UI 耗时 | 参考桌面设备 p95 ≤ 16 ms，争取接近 60 FPS | 先减标签、纹理层和装饰数量，低画质以稳定 30 FPS 为目标 |
| 新增地表/装饰绘制耗时 | 同条件 p95 增量 ≤ 3 ms | 调整分块、缓存、可见性剔除和缩放分级 |
| 纯美术改动的仿真吞吐 | 同设备同负载下降不超过约 5%，重复确认测量噪声 | 核查主线程争用与快照处理，不能减少模拟 Tick 掩盖回退 |
| 新增视觉缓存内存 | 初始上限建议 64 MiB | 缩小图块、限制 DPR/缓存档数、淘汰不可见块 |
| 重置/读档与相机变动 | 单独记录首帧及缓存重建 p95，与基线对照 | 分批重建装饰，避免在交互帧集中生成全部素材 |

已具备的优化基础：地形网格单次全量顶点投影 + 视口边界剔除 + 静态颜色预缓存 + 批处理网格线；立体实体统一队列每帧一次排序（实体量级为百级）。重复图元预渲染、静态与动态层分离可作为后续缓存方案的技术依据；实际收益仍需在本项目的相机运动和地形投影下验证。参见 [MDN：Canvas 性能优化](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas)。

### 8.3 实施门禁

- 本文仅为规划与现状对照；本次文档交付运行文档维护体检和差异检查。
- 后续前端实现运行 `frontend-check.js`，按[浏览器指南](./03-browser-guide.md)做视觉与交互验收；使用[性能指南](./15-profiling-and-benchmarking-guide.md)建立基线。
